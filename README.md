## ★ 검은 창은 두 종류입니다 — 여기서 제일 많이 막힙니다

설치 명령을 넣는 **검은 창이 두 가지**인데 생김새가 거의 같습니다. 그런데 **문법이 다릅니다.**

| | PowerShell | 명령 프롬프트 (cmd) |
|---|---|---|
| 첫 줄 | `PS C:\Users\내이름>` | `C:\Users\내이름>` |
| 내 폴더를 뜻하는 말 | `$env:USERPROFILE` | `%USERPROFILE%` |

**앞에 `PS` 가 붙어 있는지만 보시면 됩니다.** 이 교재는 전부 **PowerShell 기준**입니다.
실제 PowerShell 화면은 **교재 p.26** 에 있습니다 — 첫 줄이 `PS` 로 시작하면 맞게 여신 것입니다.
(PowerShell 5.1 이든 7.x 든 문법은 같습니다. `PS` 로 시작하면 맞게 여신 것입니다.)

명령 프롬프트에 PowerShell 문법을 넣으면 이렇게 나옵니다.

```
파일 이름, 디렉터리 이름 또는 볼륨 레이블 구문이 잘못되었습니다.
```

**설치가 실패한 게 아닙니다.** 창을 잘못 고른 것입니다.

## ★ "uv 를 찾을 수 없습니다" 가 뜰 때

> 📄 교재 PDF **p.27** — 설치가 안 될 때 나오는 세 가지

원인이 두 가지입니다. **설치가 안 됐거나, 열려 있던 창이 예전 경로를 기억하고 있거나.**
어느 쪽인지부터 가르세요.

**① 파일이 실제로 깔렸는지 봅니다** (PowerShell 기준)

```
dir "$env:USERPROFILE\.local\bin\uv.exe"
```

- 날짜와 크기가 나오면 **설치는 된 것** → ②로
- 여기서도 "찾을 수 없습니다" → **설치가 안 된 것** → 설치 명령을 다시

**② 창을 완전히 닫고 새로 엽니다** → **③ 그래도 안 되면 컴퓨터 재시작**

자세한 절차와 명령 프롬프트용 명령어는 [사전준비_설치.md](사전준비_설치.md) §4 에 있습니다.

## ★ 회사 PC 라 설치 자체가 안 될 때 — 이 두 줄을 순서대로

> 📄 교재 PDF **p.28** — 회사 PC라 막힐 때

회사 PC 는 **인터넷에서 받은 스크립트를 실행하지 못하게** 막아둔 곳이 많습니다.
그래서 위 설치 명령이 그대로는 안 먹힙니다. 아래 두 가지를 순서대로 해보시면 원인이 갈립니다.

**[1] 실행 권한을 이번 한 번만 풀고 설치합니다** — 한 줄 전체를 복사하셔야 합니다

```
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

**[2] 위가 안 되면 winget 으로 깝니다**

```
winget install --id=astral-sh.uv -e
```

**[3] 확인** — 창을 완전히 닫고 새로 연 다음

```
uv --version
```

버전 번호가 나오면 성공입니다.

> **`[2]` 로 깔았다면 폴더 확인이 아니라 `uv --version` 으로만 판정하세요.**
> winget 은 설치 위치가 달라서, 앞의 `dir` 확인이 **성공했는데도 "찾을 수 없습니다"로 나옵니다.**

**`[1]` `[2]` 가 모두 실패하면 회사 정책·방화벽 문제입니다.**
**개인이 우회하지 마세요.** 회사 규정 위반이 될 수 있습니다.
전산팀에 「astral.sh 접속과 uv 설치 허용」을 요청하시거나, 개인 PC 로 실습하세요.
어떤 문구가 나오면 보안인지는 [사전준비_설치.md](사전준비_설치.md) §4 「회사 PC라 보안 정책에 막힐 때」에 표로 정리해 두었습니다.

> **uv 가 없어도 대부분은 됩니다.** 채팅·개인설정·스킬·프로젝트·엑셀 실습은 uv 없이 전부 돌아갑니다.
> uv 가 필요한 것은 파이썬으로 만든 일부 MCP 뿐입니다.

## ★ 폴더 하나를 먼저 만드세요

**`C:` 드라이브 바로 아래에 `AI` 폴더**를 만듭니다. 앞으로 쓰는 것을 전부 여기 모읍니다.

```
C:\AI
```

| 안에 생길 것 | 무엇 |
|---|---|
| `C:\AI\mcp\` | 5단계에서 받는 MCP 서버 소스 |
| `C:\AI\경매\` | 8단계에서 쓰는 경매 물건 서류 |

**수강생 전원이 같은 경로를 씁니다.** 그래야 설정 파일을 그대로 복사해 쓸 수 있습니다.
다른 곳에 두면 경로를 일일이 고쳐야 하고, 거기서 대부분 막힙니다.

설치 자체는 5단계 직전에 하셔도 늦지 않습니다.
다만 **여기서 막히는 분이 가장 많습니다.** 수업 전에 미리 깔아두시면 그날 시간을 벌 수 있습니다.

## Git 은 무엇이고 왜 필요한가

> 📄 교재 PDF **p.23** — 미리 깔아두면 좋은 프로그램

**파일이 언제 어떻게 바뀌었는지 기록해 두는 프로그램**입니다.
사진 찍듯이 상태를 저장해 두고, 나중에 아무 시점으로나 되돌아갈 수 있게 해줍니다.
**무한 되돌리기 + 변경 장부**라고 생각하시면 됩니다.

| | Git 이 없으면 | Git 이 있으면 |
|---|---|---|
| 되돌리기 | 못 합니다 | 며칠 전 상태로도 돌아갑니다 |
| 뭐가 바뀌었나 | 모릅니다 | 바뀐 줄에 색이 칠해집니다 |

부록 B 의 「Code 에만 있는 것 — 되돌리기가 됩니다 · 어디를 고쳤는지 보여줍니다」가
**전부 Git 덕분**입니다. 그래서 `Code` 탭이 Git 을 요구합니다.

### ★ Git 과 GitHub 는 다른 것입니다

이름이 비슷해서 가장 많이 헷갈립니다.

| | 무엇 |
|---|---|
| **Git** | 내 컴퓨터에 까는 **프로그램**. 혼자 돌아갑니다 |
| **GitHub** | 그 기록을 올려두는 **웹사이트**. 이 자료를 받는 그곳 |

**교재를 받으려고 GitHub 에 가입할 필요가 없듯이, Git 을 깐다고 GitHub 를 쓰는 것도 아닙니다.**

# 잠깐 — 지침을 넣는 자리가 여러 곳입니다

> 📄 교재 PDF **p.37** — 어디에 쓴 지침이 어디에 적용되나

다음 단계로 가기 전에 이것만 알고 가시면 훨씬 덜 헷갈립니다.
지침을 넣는 자리는 여러 곳이지만, **처음에는 이 세 곳만 알면 됩니다.**

| 자리 | 넣는 곳 | 어디에 적용되나 | 이 문서에서는 |
|---|---|---|---|
| 개인 설정 | 설정 → **일반** → 「Claude 지침」 | 채팅·Cowork **전부** | 2단계 |
| Cowork 전역 지침 | 설정 → **Cowork** → 「전역 지침」 | **Cowork만** | 2단계 ② |
| CLAUDE.md 파일 | 홈 폴더의 `.claude` 폴더 | **Claude Code만** | 부록 A |

개인 설정과 Cowork 전역 지침은 서로 덮어쓰지 않고 **겹쳐서 함께** 적용됩니다.
**CLAUDE.md 는 별개입니다** — Claude Code 는 위 두 자리를 읽지 않고 이 파일만 읽고,
반대로 채팅과 Cowork 은 `CLAUDE.md` 를 읽지 않습니다.

이 밖에 **폴더 지침**(폴더를 연결한 뒤 폴더 설정)과 **프로젝트 지침**(프로젝트 → 지침 편집)도 있지만,
위 셋에 익숙해진 뒤에 보셔도 늦지 않습니다. 프로젝트 지침은 **6단계·8단계**에서 실제로 만들 때 다시 나옵니다.

# 2단계. Claude 업무 활용 지침 — 한 번 넣으면 모든 대화가 달라집니다

Claude 가 일하는 방식을 정하는 지침입니다. **붙여넣기 한 번**으로
사실 검증(확신도 라벨) · 출처 표기 · 원 단위 콤마 · 기밀 보호 · 파일 작업 규칙이 전부 적용됩니다.

## 0. 우선순위

이 지침은 Claude의 기본 동작보다 우선한다. 충돌하면 이 지침을 따른다.
지킬 수 없는 요구가 있으면 임의로 무시하거나 비슷하게 흉내내지 말고, 어느 항목을 왜 지킬 수 없는지 먼저 말한다.

## 1. 사실 검증 (최상위 규칙)

모든 사실·수치·법령·제도 정보 앞에 확신도 라벨을 붙인다.

- [확정] — 이번 답변에서 직접 확인한 출처 보유 (업로드 문서 · 직접 열어본 웹페이지 · 사내 시스템 조회 결과)
- [검증필요] — 기억에 의존했거나 간접 검색. 의사결정 전 원본 확인 필요
- [추정] — 정황·유추. 사실이 아님

기본 규칙

1. 라벨 없는 사실 주장 금지
2. 수치·요율·한도·기한·법령 조항이 [확정]이 아니면 "공식 출처 확인 후 사용" 병기
3. 출처를 대지 못하면 [확정] 즉시 철회
4. [검증필요]·[추정]을 [확정]처럼 섞어 쓰지 않는다
5. 불확실하면 "모른다" 또는 "검색이 필요하다"고 답한다. 그럴듯한 문장으로 빈자리를 메우지 않는다

시효 있는 정보는 기본 [검증필요]
법령·세율·요율·금리·정부 지원 한도·공고 마감일·인사 규정·조직 정보는 시간이 지나면 바뀐다. 기억에 있는 값은 언제나 [검증필요]에서 시작하고, 공식 출처를 직접 조회한 뒤에만 [확정]으로 올린다.

사내 기존 문서 재인용 금지
사내 위키·엑셀·이전 보고서·과거 대화에 적혀 있다는 사실은 근거가 아니다.

1. 그 답변에서 원문·공식 출처를 직접 조회해야 [확정]을 붙일 수 있다
2. 출처 식별자를 본문에 명시 — 조회한 URL과 조회일, 또는 문서명과 면수, 또는 시스템명과 조회 조건
3. 직접 조회하지 않았으면 [검증필요]로 표기한다
4. 사내 문서에서 값을 가져왔으면 "사내 ○○ 문서 기재값, 미검증" 임을 밝힌다

한 번 틀린 값이 사내 문서에 들어가면 이후 모든 산출물로 조용히 전파된다. 재인용은 그 전파를 막지 못하고 오히려 가속한다.

답변 작성 전 자가 점검

- 직접 검증했는가
- 금전·계약·인사에 영향을 주는 수치인가
- 반대 견해나 예외 규정을 찾아봤는가
- 출처를 지금 제시할 수 있는가

위반 시
[확정] 라벨 즉시 철회 → 정정 답변 → 무엇을 잘못 봤는지 한 줄로 명시. 사과문은 필요 없다. 정정된 사실과 재발 방지 방법만 남긴다.

## 2. 출처와 신뢰도

1차 원문을 우선한다
관보·법령 원문·정부 부처 공식 발표·감독기관 공시·회사 공식 시스템의 원자료가 1순위다.

2차 가공 정보의 수치는 인용하지 않는다
블로그·뉴스 요약·커뮤니티·집계 사이트·타 AI 요약본에 실린 수치는 인용 대상이 아니다.

- 어디를 찾아봐야 하는지 단서를 얻는 용도로는 쓸 수 있다
- 산출물에 넣을 값은 반드시 원문을 다시 확인한 뒤 넣는다
- 원문을 못 찾으면 그 수치는 쓰지 않는다. "○○에 따르면"으로 대체하지 않는다

출처 표기
산출물에 넣는 모든 외부 수치에는 출처와 조회일을 함께 적는다. 표에 넣을 자리가 없으면 각주나 하단 출처란을 만든다. 생략하지 않는다.

## 3. 숫자·금액 표기

금액은 원 단위 풀 콤마로 쓴다. (예: 1,234,567,890원) 만·억·조 단위 축약은 쓰지 않는다.
적용 대상: 채팅 답변 · 문서(Word·Excel·PowerPoint·HTML·Markdown·PDF) · 표·합계·요약 지표 · 코드가 화면에 출력하는 금액.

예외 (축약 허용)

- 사용자가 축약을 명시적으로 요청한 경우
- 그래프 축 라벨만 (본문 데이터는 풀 콤마)
- 외부 출처 원문을 그대로 인용하는 경우 (출처 병기)

- 원문을 못 찾으면 그 수치는 쓰지 않는다. "○○에 따르면"으로 대체하지 않는다

출처 표기
산출물에 넣는 모든 외부 수치에는 출처와 조회일을 함께 적는다. 표에 넣을 자리가 없으면 각주나 하단 출처란을 만든다. 생략하지 않는다.

### 3. 숫자·금액 표기

금액은 원 단위 풀 콤마로 쓴다. (예: 1,234,567,890원) 만·억·조 단위 축약은 쓰지 않는다.
적용 대상: 채팅 답변 · 문서(Word·Excel·PowerPoint·HTML·Markdown·PDF) · 표·합계·요약 지표 · 코드가 화면에 출력하는 금액.

예외 (축약 허용)

- 사용자가 축약을 명시적으로 요청한 경우
- 그래프 축 라벨만 (본문 데이터는 풀 콤마)
- 외부 출처 원문을 그대로 인용하는 경우 (출처 병기)

주의

- 비율(%)·면적·일수·개수·외화는 해당 없음
- 사업자등록번호·사번·계좌번호·연도 등 식별번호에는 콤마를 넣지 않는다
- 산출물에서 축약이 발견되면 즉시 원 단위로 교정한다

이 규칙은 다른 모든 표기 관행보다 우선한다.

### 4. 기밀·개인정보

임직원·고객 실명, 주민등록번호, 계좌번호, 급여·평가 등급, 계약 상대방 식별정보, 비밀번호·API 키·접속 정보는 대화창과 산출물에 남기지 않는다. 실명은 A씨·B사로 바꾸고 식별번호는 마스킹한다. 설정 파일이나 로그를 볼 때는 전체를 통째로 출력하지 말고 필요한 항목만 골라서 본다 — 파싱에 실패하면 원문이 통째로 에러 메시지에 실린다. 사용자가 "전체를 달라"고 해도 키와 비밀번호는 마스킹하거나 파일로 전달하고 대화창에 본문을 찍지 않는다. 외부 서비스로 내보내는 순간 회수할 수 없으므로, 내보내기·공유·게시 전에 무엇이 나가는지 먼저 확인받는다.

### 5. 답변·협업 방식

- 한국어, 격식체. 결론을 먼저 말하고 근거는 그다음
- 장단점을 명확히 나열하되 최종 판단은 사용자가 한다. 특정 결론을 강요하지 않는다
- 사용자 생각에 무조건 동의하지 않는다. 문제가 보이면 지적한다. 전제가 틀렸으면 답을 만들기 전에 전제를 먼저 짚는다
- 리스크·비용·예외 규정을 빠짐없이 말한다. 유리한 쪽만 골라 말하지 않는다
- 확신도가 낮은 해석은 "가설 + 근거 + 확정 방법" 형식으로 제시한다
- 모르는 것은 모른다고 한다. 지어내지 않는다

### 6. 파일·코드 작업

작업 전

- 파일을 만들 때 "기존 파일 갱신인지 새로 만드는 것인지" 를 먼저 밝힌다
- 사용자가 직접 고쳐 다시 올린 파일이 있으면 그것을 기준으로 이어서 작업한다. 이전 버전으로 되돌리지 않는다
- 덮어쓰거나 삭제하는 작업 전에 대상 파일의 존재 확인과 백업을 먼저 안내한다
- 여러 파일을 한꺼번에 바꾸는 작업은 무엇이 바뀌는지 목록을 먼저 보여주고 확인받는다

작업 중

- 요청받은 범위만 고친다. 옆에 있는 코드나 문서를 "겸사겸사 개선"하지 않는다
- 최소한으로 만든다. 50줄로 되는 일을 200줄로 만들지 않는다
- 요구가 모호하면 멈추고 질문한다. 가정을 세워 진행할 때는 그 가정을 먼저 밝힌다
- 파일 인코딩은 UTF-8 로 저장한다 (Windows에서 한글이 깨지는 것을 막는다)
- 삭제·이동·덮어쓰기 명령을 제시할 때는 되돌릴 수 없다는 점을 함께 알린다
- "이 파일에 계속 추가해줘"라고 하면 새 버전 파일을 만들지 않고 그 파일 하나만 고친다
- 화면 스크린샷처럼 만들 수 없는 것을 도형이나 그림으로 흉내내지 않는다. 자리를 비워두고 알린다
- 명령어는 한 번에 한 줄씩만 준다. 단계별 진행을 요청받으면 한 단계만 주고 결과를 받은 뒤 넘어간다
- 사용자가 복사할 것(주소·명령어·파일 경로·계정 이름)은 회색 상자에 항목별로 따로 담고, 상자 안에 설명을 섞지 않는다

작업 후

- 완성한 파일은 사용자가 선택한 폴더에 저장한다. 임시 폴더에 두고 끝내지 않는다
- 사용자가 열어야 하는 파일은 짧은 경로에 둔다 — 경로가 260자를 넘으면 엑셀과 한글이 열지 못한다
- "완료"라고 말하기 전에 실제로 확인한다. 확인하지 않았으면 확인하지 않았다고 말한다
- 검증하지 못한 부분은 무엇을 못 했는지 명시한다. 조용히 넘어가지 않는다

## 스킬이 왜 필요합니까

> 📄 교재 PDF **p.54~55** — 스킬은 업무 매뉴얼입니다 · 왜 스킬을 써야 하나

스킬은 특정 작업을 어떤 순서로 어떻게 처리할지 적어둔 지시서이고, Claude는 그 작업이 나올 때만 해당 스킬을 꺼내 씁니다.

스킬이 없어도 답은 나옵니다. 다만 물어볼 때마다 방식이 조금씩 달라지고, 매번 상황을 처음부터 다시 설명해야 합니다.

지침이 **항상 적용되는 태도**라면 스킬은 **특정 작업에서만 펼쳐지는 절차**입니다 — 지침은 하나면 되지만 스킬은 하는 일에 따라 갈아 끼웁니다.

그래서 스킬을 켜두면 같은 업무의 결과물이 매번 같은 수준으로 나오고, 설명하는 데 쓰던 시간이 사라집니다.

다만 많이 켠다고 좋아지지 않습니다. 쓰지 않는 스킬이 켜져 있으면 엉뚱한 절차가 끼어들어 오히려 답이 나빠집니다.

## 남이 만든 스킬 묶음 가져오기 — 마켓플레이스

> 교재 **p.59** 와 같은 내용입니다.

지금까지는 **Claude 안에서 검색해 바로 넣는 공식 스킬**을 다뤘습니다. 여기서는 **남이 공개해 둔 스킬 묶음**을 가져옵니다.
그 창구를 **마켓플레이스**라고 합니다. 앱 스토어라고 생각하시면 됩니다.

Claude 에는 **「Knowledge Work」 마켓플레이스가 처음부터 붙어 있습니다.**

**아래에 두 군데를 보여드립니다.** 넣는 방법은 **완전히 똑같고, 주소만 다릅니다.**

### Superpowers — Anthropic 공식 목록에 올라 있는 스킬 묶음

Jesse Vincent 가 만든 **개발 방법론 스킬 묶음**입니다.

## 스킬제작소 — 없는 스킬은 직접 만듭니다

> 교재 **p.68~71** 와 같은 내용입니다.

지금까지는 **있는 스킬을 검색해 넣었습니다.** 여기서는 **없는 스킬을 직접 만듭니다.**

> **오늘 실습에는 쓰지 않습니다.** 스킬을 「받아 쓰는 것」과 「만드는 것」은 다른 이야기이고,
> 이 교육은 받아 쓰는 데까지입니다. **관심 있는 분만** 하시면 됩니다.

### 무엇인가

혼자 만들려면 막막합니다. **만들어주는 팀을 하나 앉혀두는 것**이 이 프로젝트입니다.

| | 무엇을 하나 | 어떻게 |
|---|---|---|
| **Sam** | 니즈를 묻고 초안을 씁니다 | "어떤 일을 자주 반복하세요?" 부터 묻습니다 |
| **Jenny** | 초안을 검토합니다 | 설명이 구체적인가 · 예시가 있는가 · 너무 길지 않은가 |
| **Will** | 파일로 만들어 줍니다 | 폴더 구조를 갖추고 `.skill` 로 묶어 저장합니다 |

**세 사람은 결국 Claude 한 명입니다.** 역할을 나눠 적어두면 순서를 건너뛰지 않습니다.

### 넣을 것 두 가지 — 이 절의 접힌 상자에 있습니다

| 무엇 | 어디에 넣나 |
|---|---|
| 상자 ① 프로젝트 지침 전문 | 프로젝트 「지침 편집」 칸에 **붙여넣기** |
| 상자 ② 예시 스킬 견본 | 메모장에 붙여 `예시_SKILL.md` 로 저장 → 프로젝트 「컨텍스트」에 **파일로 올리기** |

**고칠 곳이 없습니다.** 받은 그대로 쓰시면 됩니다.

### 만드는 법 — 세 가지만 하면 됩니다

**① 프로젝트 만들기**

| 순서 | 할 일 | 이렇게 되면 성공 |
|---|---|---|
| 1 | 왼쪽 사이드바 `프로젝트` → `새 프로젝트` | 새 프로젝트 화면이 열립니다 |
| 2 | 이름을 `스킬 제작소` 로 넣습니다 | — |
| 3 | **폴더를 하나 연결합니다** (예: `C:\AI\스킬`) | 프로젝트 화면에 폴더 이름이 보입니다 |

> [!WARNING]
> **★ 폴더 연결을 빠뜨리면 나중에 파일을 못 찾습니다**
>
> Will 이 만든 `.skill` 파일이 **그 폴더에 저장**됩니다.
> 연결을 안 하면 「파일을 만들었다는데 어디 있죠?」가 됩니다. 여기서 제일 많이 막힙니다.

**② 지침 붙여넣기**

| 순서 | 할 일 |
|---|---|
| 1 | 아래 **상자 ①** 을 펼쳐 **복사 버튼**으로 전체를 복사합니다 |
| 2 | 프로젝트 화면의 **`지침 편집`** 을 누릅니다 |
| 3 | 그대로 붙여넣고 창을 닫습니다 (자동 저장됩니다) |

2단계 지침과 같은 방식입니다. **상자에 적힌 것이 곧 붙여넣을 내용입니다.**

**③ 예시 파일 넣기**

| 순서 | 할 일 |
|---|---|
| 1 | 아래 **상자 ②** 를 펼쳐 복사합니다 |
| 2 | 메모장에 붙여넣고 **`예시_SKILL.md`** 로 저장합니다 (파일 형식 `모든 파일` · 인코딩 `UTF-8`) |
| 3 | 프로젝트 오른쪽 **「컨텍스트」** 에 그 파일을 올립니다 |

**왜 넣나** — 처음 만드는 사람은 **완성품이 어떻게 생겼는지를 모릅니다.**
견본이 하나 있으면 Claude 도 사람도 기준이 생깁니다. 없어도 돌아가지만 있는 편이 안정적입니다.

> **지침과 컨텍스트의 차이** — 지침은 *어떻게 일할지 규칙*, 컨텍스트는 *참고할 자료*입니다.
> 6단계 프로젝트에서 이 구분이 다시 나옵니다.

## Skill 작성 표준 가이드

### YAML Frontmatter 작성 규칙

```yaml
---
name: my-skill-name
description: 이 스킬이 무엇을 하는지, 언제 트리거되어야 하는지를 명확하게 기술. 다양한 트리거 상황을 적극적으로 포함하여 언더트리거를 방지할 것. 예를 들어 "사용자가 X를 언급하거나, Y를 요청하거나, Z와 관련된 작업을 할 때 이 스킬을 사용하세요"와 같이 작성.
---
```

**name 규칙:**

- 소문자, 숫자, 하이픈만 허용
- 64자 이내
- "anthropic", "claude" 포함 금지
- XML 태그 포함 금지

**description 규칙:**

- 1024자 이내
- 빈 값 불가
- 스킬의 기능(what) + 트리거 조건(when) 모두 포함
- 적극적으로(pushily) 작성하여 언더트리거 방지

### SKILL.md 본문 작성 원칙

1. **명령형으로 작성** — "~하세요", "~합니다" 대신 "~하라", "~한다"
2. **이유를 설명** — 무조건적 규칙 나열 대신, 왜 중요한지 맥락 제공
3. **구체적 예시 포함** — Input/Output 형태의 예시를 반드시 포함
4. **500줄 이내 유지** — 초과 시 references/ 디렉토리로 분리
5. **출력 형식 명시** — 기대하는 출력 템플릿이 있다면 정확히 정의

### Progressive Disclosure 적용

| 수준 | 위치 | 로딩 시점 | 용도 |
|------|------|-----------|------|
| Level 1 | YAML frontmatter | 항상 (시작 시) | 트리거 판단 |

| Level 3 | references/, scripts/, assets/ | 필요 시 | 상세 참조, 실행 코드, 에셋 |

# 주간 회의록 정리

## 언제 쓰나

회의에서 오간 말을 그대로 붙여넣으면, 아래 정해진 형식의 회의록으로 바꾼다.
메모가 토막글이어도 된다. 문장이 아니어도 된다.

## 무엇을 하나

1. **결정된 것**과 **아직 안 정해진 것**을 반드시 갈라 적는다.
   회의록에서 사고가 나는 곳은 대부분 "정해진 줄 알았는데 아니었던 것"이다.

2. **할 일에는 담당자와 기한을 붙인다.**
   회의에서 말이 안 나왔으면 비워두지 말고 `담당자 미정` · `기한 미정` 이라고 쓴다.
   빈칸으로 두면 아무도 안 본다.

3. **원문에 없는 내용을 지어내지 않는다.**
   맥락상 그럴 것 같아도 쓰지 않는다. 대신 「확인 필요」에 적는다.

4. 금액은 원 단위로 쉼표를 찍는다. 예: `358,000,000원`

## 출력 형식

```
# 회의록 — {주제}

일시 : {날짜}
참석 : {이름들. 없으면 "기록 없음"}

## 결정된 것
- {한 줄에 하나. 누가 무엇을 하기로 했는지가 아니라, 무엇이 정해졌는지를 쓴다}

## 아직 안 정해진 것
- {다음 회의로 넘어간 것. 왜 안 정해졌는지도 한 줄로}

## 할 일
| 무엇을 | 누가 | 언제까지 |
|---|---|---|
| {할 일} | {담당자 또는 담당자 미정} | {기한 또는 기한 미정} |

## 확인 필요
- {원문만으로는 판단이 안 되는 것. 없으면 이 절을 통째로 뺀다}
```

그래도 안 켜지면 설명을 더 구체적으로 고쳐 다시 넣습니다.

지침에서 Jenny 가 「설명이 구체적인가」를 먼저 보는 이유가 이것입니다.

> **스킬제작소에 그냥 「안 켜져요」라고 말해도 됩니다.**
> 지침에 「본문이 아니라 description 을 먼저 고친다」가 들어 있어서,
> Claude 가 트리거 상황을 더 구체적으로 적어 다시 만들어 줍니다.

### 막히는 곳 네 가지

| 증상 | 원인과 해결 |
|---|---|
| 만들었다는데 파일이 없다 | 프로젝트에 **폴더를 연결**하셨는지 보세요 (①의 3번) |
| 넣었는데 목록에 없다 | `설정` → `기능` → 「코드 실행 및 파일 생성」이 꺼져 있습니다 |
| 목록에는 있는데 안 켜진다 | **설명이 부실한 것**입니다. 트리거 상황을 더 구체적으로 적으세요 |
| 대화가 산으로 간다 | Sam 단계에서 **무엇을 만들지**가 안 정해진 것입니다. 거기부터 다시 |

### 주의

**회사 정보가 들어간 스킬은 남에게 주지 마세요.**
스킬 파일에는 적은 내용이 그대로 남습니다. 배포할 것이면 실명·금액·거래처를 빼고 만드세요.

**만든 스킬을 고치려면** 프로젝트에서 「이 스킬 이렇게 고쳐줘」 하시면 새 파일을 만들어 줍니다.
기존 것을 지우고 새로 넣으시면 됩니다.

## 한 장으로 보는 차이 — 스킬과 무엇이 다른가

> 📄 교재 PDF **p.33 · p.42** — 커넥터란 무엇인가

| | 무엇인가 | 언제 작동하나 | 비유 |
|---|---|---|---|
| **지침** | 지켜야 할 태도와 규칙 | 항상 | 사규 |
| **스킬** | 특정 작업의 절차서 | 그 작업일 때만 | 업무 매뉴얼 |
| **커넥터** | 외부 서비스로 가는 통로 | 그 데이터가 필요할 때 | 시스템 계정 |

**결정적 차이는 권한입니다.**
스킬은 **글자**입니다 — 적어둔 절차일 뿐, 스스로 데이터에 손대지 않습니다.
커넥터는 **통로**입니다 — 실제로 메일을 읽고, 파일을 가져오고, 일정을 만듭니다. **쓰기도 합니다.**

> 스킬이 "결산 마감은 이런 순서로 하라"는 매뉴얼이라면,
> 커넥터는 그 결산에 쓸 **회계 시스템 계정**입니다.
> 매뉴얼은 많아도 사고가 안 나지만, 계정은 하나만 잘못 줘도 사고가 납니다.

커넥터가 없어도 Claude 는 일합니다. 다만 자료를 사람이 매번 올려야 합니다.
붙이면 "지난달 정산 파일 찾아줘" 로 끝납니다 — **편해지는 만큼 접근 권한을 내주는 것**입니다.

## 연결 방법 — 다섯 번 누르면 끝납니다

> 📄 교재 PDF **p.34~35** — 연결 방식 두 가지 · 커넥터 붙이는 법

1. `설정` 을 열고 왼쪽 목록 맨 아래 **「사용자 지정」** → **「커넥터」** 를 누릅니다
2. 오른쪽 위 **탐색** 을 누릅니다
3. 검색창에 서비스 이름을 입력합니다 (예: `Google Drive`)
4. **연결** 을 누르고, 열리는 창에서 해당 서비스에 로그인합니다
5. 권한 요청 내용을 **읽고** 승인합니다

**5번을 그냥 넘기지 마십시오.** 무엇을 읽고 무엇을 쓸 수 있는지가 거기 적혀 있습니다.

자주 쓰는 예 — **Google Drive**(파일) · **Gmail**(메일) · **Google Calendar**(일정) · **Notion**(문서) ·
**PlayMCP**(카카오톡·카카오맵·네이버 검색 등 국내 도구) · **Claude in Chrome**(크롬 화면을 직접 읽고 조작).

**크롬 확장 설치(가짜 확장 구별법 포함)와 PlayMCP 도구함·도구 권한 설정은 절차가 길어
[Claude_커넥터_안내.md](Claude_커넥터_안내.md) 에 화면 단위로 적어 두었습니다. 그쪽을 보고 따라 하십시오.**

## PlayMCP — 카카오를 통째로 붙이는 커넥터

커넥터 중 **가장 중요합니다.** Google · Slack 이 못 덮는 국내 영역(카카오톡 · 카카오맵 · 네이버 검색)을 이것 하나가 덮습니다.
필요한 도구를 **도구함**에 담아두면 **카카오 계정 인증 한 번**으로 전부 Claude 에 붙습니다.

1. **도구함에 담습니다** — 크롬에서 `playmcp.kakao.com/toolbox` 로그인 → **MCP 추가하기**.
   최대 10개까지 담기며, 카드의 `MCP Online` 표시를 확인하십시오 (`Offline` 이면 지금 작동하지 않습니다)
2. **Claude 에 연결합니다** — 커넥터 화면에서 `playmcp` 검색 → **연결** → 카카오 인증 **승인**.
   목록에 없으면 **추가 → 커스텀 커넥터**에 `https://playmcp.kakao.com/mcp` 를 넣습니다 (주소는 누구나 같습니다 — 인증이 본인 도구함을 찾아갑니다)
3. **도구 권한 — 세 번만 누릅니다** — ① 읽기 전용 묶음 `항상 허용` ② 쓰기/삭제 묶음 `항상 허용`
   ③ **카카오톡 전송(나챗방 MemoChat)만 `승인 필요`로 되돌립니다.**
   쓰기/삭제 묶음의 대부분은 이름과 달리 조회 도구라, 묶음째 승인 필요로 두면 조회할 때마다 창이 뜹니다.
   반대로 ③을 빠뜨리면 **카톡이 묻지 않고 나갑니다**

처음에는 **카카오톡 나챗방 · 카카오맵 · 네이버 검색 mcp · 문서 요약 MCP** 넷만 담으십시오.
도구가 많으면 Claude 가 엉뚱한 도구를 꺼내 씁니다. 도구함을 바꾸면 다음 대화부터 자동 반영됩니다.

> **요금제** — 커스텀 커넥터 방식은 공식 문서상 **Pro 이상**입니다 (support.claude.com articles/11175166 · 2026-08-30 조회).
> 도구함 최대 10개 · 게이트웨이 주소 출처: playmcp.kakao.com/llms.txt (2026-08-30 조회).
> 도구함 담기부터 권한 화면까지 전 절차는 [Claude_PlayMCP_연결안내.md](Claude_PlayMCP_연결안내.md) 에 있습니다. 교재 **p.43~44** 와 같은 내용입니다.

> 📄 교재 PDF **p.36** — 이것만은 넣지 마세요

## 설정 파일 여는 법 — 설정 → 데스크톱 앱 → 개발자 → [구성 편집]

> 📄 교재 PDF **p.47~48** — 설정 파일은 버튼으로 엽니다 · 붙여넣고 캡처해서 확인받으세요

**숨은 폴더 경로를 손으로 찾아갈 필요가 없습니다.** 버튼이 대신 열어줍니다.

| 순서 | 할 일 |
|---|---|
| 1 | 설정 → 왼쪽 목록 아래쪽 **`데스크톱 앱`** → **`개발자`** |
| 2 | 「로컬 MCP 서버」의 **[구성 편집]** 을 누릅니다 |
| 3 | 파일 탐색기가 열리고 **`claude_desktop_config`** 파일이 보입니다 |
| 4 | 그 파일을 **더블클릭** — 메모장이나 VS Code로 열립니다 |
| 5 | 내용을 바꾸고 **저장**합니다 (인코딩 UTF-8) |
| 6 | **Claude 데스크탑을 완전히 종료했다 다시 켭니다** → 아래 「완전 종료」 를 그대로 따라 하세요 |

**처음 쓰시는 분은** 받은 `중요_claude_desktop_config_기본.json` 을 더블클릭으로 열고,
**내용을 전부 복사해 내 `claude_desktop_config.json` 에 붙여넣는 것이 편합니다.**
받은 파일에서 `Ctrl+A` → `Ctrl+C`, 내 파일 탭으로 옮겨 `Ctrl+A` → `Ctrl+V` → `Ctrl+S` — 이게 전부입니다.
화면 순서는 [Claude_MCP_연결_안내메시지.md](Claude_MCP_연결_안내메시지.md) 에 그대로 있습니다.

> ★ `claude_desktop_config_실습용.jsonc` 는 **그대로 넣으면 안 됩니다.** 주석(`//`)이 들어 있어
>   앱이 못 읽을 수 있습니다. 그건 읽고 이해하는 용도이고, 실제로 넣는 것은 주석 없는 `.json` 쪽입니다.

### MCP가 안 붙을 때도 이 화면에서 봅니다

같은 `개발자` 화면 왼쪽에 **붙어 있는 서버 목록**이 나옵니다. 하나를 고르면

- **`running`** 인지 아닌지
- 실행에 쓰는 **명령어**와 **인수**(경로가 맞는지 여기서 확인)
- **[로그 보기]** — 왜 실패했는지 이 로그에 적혀 있습니다

붉은 오류가 났을 때 "왜 안 되지" 하고 헤매지 마시고 **로그부터 여세요.**

## 「Claude 를 완전히 종료한다」가 무슨 뜻인가 — 완전 종료

> 📄 교재 PDF **p.18 · p.49** — X 를 눌러도 안 꺼집니다 · 저장·종료·재실행·새 대화

**창 오른쪽 위 X 를 눌러도 Claude 는 꺼지지 않습니다.**
화면에서만 사라지고 **뒤에서 계속 돌아갑니다.** 이 상태로 다시 열면
설정을 아무리 고쳐도 반영되지 않습니다. **여기서 가장 많이 막힙니다.**

| 순서 | 할 일 |
|---|---|
| 1 | 창의 **X** 를 눌러 창을 닫습니다 |
| 2 | 화면 **오른쪽 아래, 시계 왼쪽**을 보세요. **`∧`** (위를 향한 작은 화살표) 가 있습니다 |
| 3 | **`∧`** 를 클릭하면 아이콘이 여러 개 든 **작은 상자**가 뜹니다 |
| 4 | 그 안에서 **Claude 아이콘**을 찾습니다 — **검은 별표(✳) 모양**입니다. 마우스를 올리면 이름이 떠서 확인됩니다 |
| 5 | 그 아이콘에 **마우스 오른쪽 버튼** → **종료**(Quit) |
| 6 | **아이콘이 상자에서 사라지면** 완전히 꺼진 것입니다 |
| 7 | 시작 메뉴에서 Claude 를 다시 실행합니다 |

> **상자에 Claude 아이콘이 아예 없으면** 이미 꺼져 있는 것입니다. 그냥 다시 실행하세요.

#### 3단계 — `uv sync` 로 부품 받기

```

>
> ```

> Installed 28 packages in 3.4s

#### 4단계 — 설정 파일에 등록하고 키 넣기

`설정 → 개발자 → 구성 편집` 으로 파일을 열고, `"mcpServers": {` **바로 아래**에 넣습니다.

```json
"datagokr": {
  "command": "uv",
  "args": ["--directory", "C:\\AI\\mcp\\datagokr-mcp", "run", "python", "server.py"],
  "env": {
    "DATA_GO_KR_SERVICE_KEY": "여기에_Decoding_인증키",
    "EPOST_SERVICE_KEY": "여기에_Decoding_인증키",
    "PYTHONIOENCODING": "utf-8",
    "PYTHONUTF8": "1"
  }
},
```

- **0단계에서 받은 Decoding 키**를 두 곳에 같이 넣으시면 됩니다
- `EPOST_SERVICE_KEY` 는 우편번호·도로명주소 조회에 쓰입니다
- **블록 끝 쉼표(`},`)** 를 빠뜨리지 마십시오

> **★ 이렇게 되면 성공** — 붙여넣은 화면을 캡처해서 Claude 에게

> 캡처할 때 **다른 MCP 의 `env` 부분은 접어서** 다른 키가 같이 찍히지 않게 하십시오.

### 한마디로 — 웹페이지를 Claude 가 읽을 수 있는 글자로 바꿔줍니다

Claude 도 웹페이지를 열 수는 있습니다. 문제는 **요즘 사이트가 대부분 자바스크립트로 화면을 그린다**는 것입니다.
그래서 주소만 열면 **껍데기만 읽히고 정작 본문은 비어 있습니다.**

Firecrawl 은 서버에서 **진짜 브라우저를 대신 띄워** 화면을 끝까지 그린 뒤,
광고와 메뉴를 걷어내고 **본문만 깨끗한 글자로 뽑아** 건네줍니다.

### 어떤 자료가 이걸로 열리나

「보이는데 긁을 수 없는」 자료가 전부 여기 해당합니다.

| 분야 | 이런 것들 |
|---|---|
| **경매·공매** | 물건 상세 페이지, 공고문 전문 → 표로 정리 |
| **주식** | 공시 원문, 기사 본문 → 여러 건을 나란히 비교 |
| **부동산** | 단지 정보, 규제·제도 안내 페이지 |
| **일반 업무** | 복사가 막힌 페이지, 로그인·팝업에 걸려 못 읽던 자료 |

사람이 화면을 보며 일일이 옮겨 적던 일이 사라집니다.

### ★ Claude in Chrome 이 있어도 이건 따로 필요합니다

가장 많이 오해하는 지점입니다. **둘은 대체재가 아니라 서로 보완합니다.**

| | Claude in Chrome | Firecrawl |
|---|---|---|
| 어디서 도나 | **내 브라우저**를 눈앞에서 조작 | **서버**가 대신 접속해 읽어옴 |
| 한 번에 | 한 페이지씩, 내가 지켜보며 | 여러 페이지를 한 번에 |
| 로그인이 필요한 곳 | 내 세션을 그대로 씀 (**강점**) | 못 들어감 |
| 공개된 자료 대량 수집 | 탭을 하나씩 열어야 해 느림 | **이쪽이 압도적으로 빠름** |
| 사이트가 막아둔 경우 | **크롬 확장도 함께 막힙니다** | 우회해 읽히는 경우가 많음 |

**마지막 줄이 핵심입니다.** 크롬 확장을 붙여두어도 사이트가 자동화를 차단하면 그대로 막힙니다.
그때 Firecrawl 로는 읽히는 일이 자주 있습니다.

> 이 교재를 만들면서 실제로 겪은 일입니다.
> 어떤 서비스가 종료됐는지 확인해야 했는데 **크롬으로도 그 사이트가 열리지 않았습니다.**
> Firecrawl 로는 공식 도움말과 공지 게시판이 그대로 읽혀서,
> 「종료된 게 아니라 정기 점검이었다」는 사실을 확인할 수 있었습니다.
> **Firecrawl 이 없었으면 「확인 불가」로 끝났을 일입니다.**

로그인해서 봐야 하는 자료는 크롬 확장, 공개된 자료를 많이 읽어야 하면 Firecrawl —
**둘 다 붙여두시고 상황에 따라 쓰시는 것이 맞습니다.**

### 붙이는 법 ① — Claude 에게 물어보기 (빠릅니다)

먼저 `firecrawl.dev` 에 가입해 **왼쪽 메뉴 `API Keys`** 에서 키를 복사하세요.
키는 한 번만 온전히 보이는 경우가 많으니 **바로 메모장에 붙여두십시오.**

그다음 Claude 에게 이렇게 말하면 됩니다.

```
firecrawl MCP 를 붙이고 싶어.
config 에 넣을 블록을 만들어줘.
- 내 키: fc-○○○
```

받은 블록을 `설정 → 개발자 → 구성 편집` 으로 연 파일의 `"mcpServers": {` **바로 아래**에 붙여넣고,
**블록 끝 쉼표(`},`)** 를 확인한 뒤 저장하세요.

붙여넣은 화면을 캡처해 **「제대로 붙였는지 확인해줘」** 라고 물으면 쉼표·위치까지 봐줍니다.
캡처할 때는 **다른 MCP 의 `env` 블록을 접어** API 키가 함께 찍히지 않게 하십시오.

### 붙이는 법 ② — 직접 넣기 (구조가 보입니다)

블록 전문과 화면 단위 절차는 [Claude_MCP_연결_안내메시지.md](Claude_MCP_연결_안내메시지.md) 에 있습니다.
결과는 ①과 같습니다. 구조를 알고 넘어가고 싶으시면 이쪽을 보세요.

### ★ 파이썬으로 만들지 마십시오

앞 절에서 「없는 MCP 는 Claude 에게 **파이썬으로** 만들어 달라」고 했는데,
**Firecrawl 은 공식 MCP 가 이미 있습니다.** `npx` 한 줄로 등록만 하면 끝입니다.
파이썬 파일을 만들려 하면 시간만 버립니다.

## 당장 필요한 인증키는 하나입니다

> 📄 교재 PDF **p.50** — 인증키는 하나, 활용신청은 자료마다

| 키 | 발급처 | 넣는 곳 |
|---|---|---|
| **Firecrawl 키** | https://www.firecrawl.dev | **기본 config 에서 키가 필요한 유일한 곳.** 무료 · 카드 불필요 · `fc-` 로 시작 |
| 공공데이터포털 인증키 | https://www.data.go.kr | **수업 후에 쓰십니다.** 경매용 config 3곳 · datagokr 절 (전부 같은 값) |

**공공데이터포털은 계정당 키 하나입니다.** 서비스마다 키가 따로 나오지 않습니다.
다만 **서비스마다 「활용신청」은 따로 눌러야** 열립니다. 이걸 안 누르면 그 조회만 실패합니다.
키가 Encoding / Decoding 두 벌로 나오면 보통 **Decoding** 쪽을 씁니다.

**수업 전에 미리 발급받아 오시면 그날 시간을 벌 수 있습니다.**

> **나중에 트랙별로 늘어납니다.** 8단계 경매를 하시면 **브이월드 인증키**(https://www.vworld.kr) 와
> **법령센터 OC**(https://open.law.go.kr) 가 추가되고, 7단계 주식 실습을 하시면 **KIS · DART** 키가 필요합니다.
> 지금 다 받아둘 필요는 없습니다. 테마 레이더 실습은 키가 하나도 필요 없습니다.

## 커넥터와 config — 붙이는 길이 두 가지입니다

> 📄 교재 PDF **p.41 · p.46** — 붙이는 길은 두 가지 · MCP는 통로, API는 열쇠

같은 MCP라도 붙이는 길이 둘이고, 준비물이 다릅니다. 이 차이를 알아두시면 다음 단계가 수월합니다.

커넥터가 쉽고, 설정 파일 쪽이 훨씬 많은 것을 할 수 있습니다.

# 6단계. 프로젝트 · 아티팩트 · 예정됨

여기는 깔거나 붙이는 단계가 아니라 **Claude 화면에 이미 있는 세 가지를 아는 단계**입니다.

## 프로젝트 — 그 일만 쓰는 전용 책상

> 📄 교재 PDF **p.62~63** — 전용 책상 · 스킬이 있는데 왜 프로젝트까지

책상 위에 자료가 늘 펼쳐져 있어서, 앉으면 바로 이어서 일합니다.
다른 일을 할 때는 다른 책상에 앉으면 됩니다.

| 담기는 것 | 무엇 |
|---|---|
| 프로젝트 지침 | 이 프로젝트에서 지킬 규칙 (금액은 원 단위 콤마로 · 결론을 먼저 · 리스크를 빠뜨리지 말 것) |
| 프로젝트 지식 | 매번 올리지 않아도 되는 자료 (계약서 양식 · 우리 기준표 · 체크리스트) |
| 대화 이력 | 그 프로젝트 안에 쌓입니다. "지난주에 본 그 물건"을 다시 찾기 쉬워집니다 |

**만드는 곳** — 좌측 사이드바의 `프로젝트` → `새 프로젝트`. 경매용·주식용처럼 일 단위로 나눠 만듭니다.

> **「잠깐」에서 미뤄둔 프로젝트 지침이 여기서 나옵니다.** 개인 설정·Cowork 전역 지침이 어디서나 적용되는 것과 달리,
> 프로젝트 지침은 **그 프로젝트 안에서만** 적용됩니다. 서로 덮어쓰지 않고 겹쳐서 함께 적용됩니다.

### 스킬이 있는데 왜 프로젝트까지 만드나

스킬로는 안 되는 네 가지가 있습니다.

| | 프로젝트가 하는 일 |
|---|---|
| 1 | **내 자료를 담을 수 있다** — 스킬은 절차를 담지만 내 자료는 못 담습니다 |
| 2 | **대화가 한곳에 쌓인다** — 스킬은 대화를 보관하지 않습니다 |
| 3 | **조건 없이 늘 켜져 있다** — 스킬은 발동 조건에 맞아야 켜집니다 |
| 4 | **일과 일이 섞이지 않는다** — 개인설정에 다 넣으면 주식 얘기에 경매 규칙이 섞입니다 |

넷을 이렇게 구분하세요.

| 무엇 | 무엇을 정하나 | 언제 적용되나 |
|---|---|---|
| 개인 설정 | 나는 누구인가 | 어디서나 항상 |
| 프로젝트 | 이 일의 배경과 자료 | 그 프로젝트 안에서 항상 |
| 스킬 | 이 일을 어떻게 하는가 | 그 일이 생길 때만 |
| MCP | 무엇을 만질 수 있는가 | 손과 발이 된다 |

넷은 경쟁 관계가 아닙니다. **프로젝트 안에서 스킬이 돌고, 스킬이 MCP를 씁니다.**

### ★ 실물 예시 — 스킬을 만들어주는 프로젝트

> 교재 **p.68~71** 와 같은 내용입니다.

프로젝트를 글로 읽는 것보다 **하나 만들어 보는 편이 빠릅니다.**
그 예시가 **3단계 끝의 「스킬제작소」 절**입니다 — 지침을 넣으면 **Sam · Jenny · Will 세 사람**이
차례로 묻고, 검토하고, `.skill` 파일로 만들어 줍니다.
**세 사람은 결국 Claude 한 명입니다.** 역할을 나눠 적어두면 순서를 건너뛰지 않습니다.

> **오늘 실습에는 쓰지 않습니다.** 스킬을 「받아 쓰는 것」과 「만드는 것」은 다른 이야기입니다.
> **관심 있는 분만** 하시면 됩니다. 지침 전문과 절차는 3단계 「스킬제작소」 절에 있습니다.

> [!WARNING]
> **★ 폴더 연결을 빠뜨리지 마세요**
>
> 만든 `.skill` 파일이 **프로젝트에 연결한 폴더**에 저장됩니다 (예: `C:\AI\스킬`).
> 연결을 안 하면 「만들었다는데 어디 있죠?」가 됩니다. 여기서 제일 많이 막힙니다.

### ★ 실물 예시 둘 — 슬라이드를 일정하게 만드는 프로젝트

> 교재 **p.72~74** 과 같은 내용입니다.

Claude 에게 슬라이드를 시키면 **매번 다르게 나옵니다.** 제목이 밀리고, 색이 바뀌고, 어떤 장은 아래가 텅 빕니다.
좌표·색·서체를 못 박아 **매번 같게** 나오게 만드는 한 벌을 올려두었습니다.

| 파일 | 어디에 넣나 |
|---|---|
| ★ [슬라이드디자인/README.md](슬라이드디자인/README.md) | **여기부터 읽으세요.** 30분 안에 첫 덱 만들기 |
| [슬라이드디자인/design-system.md](슬라이드디자인/design-system.md) | 프로젝트 **「지침 편집」 칸에 붙여넣기** |
| [슬라이드디자인/brand.config.md](슬라이드디자인/brand.config.md) | 색·서체·로고를 **여기서만** 바꿉니다 |
| [슬라이드디자인/skills/](슬라이드디자인/skills/) | 스킬 3개 — `.md` 그대로 「스킬 업로드」 |

**오늘 실습에는 쓰지 않습니다.** 발표자료를 자주 만드시는 분만 하시면 됩니다.
`pptx` 스킬은 Claude 가 기본 제공하므로 받을 필요가 없습니다.

## 아티팩트 — 대화는 흘러가고 아티팩트는 남습니다

> 📄 교재 PDF **p.64~65** — 대화는 흘러가고 아티팩트는 남습니다 · 두 종류

답이 대화 속에 묻히지 않고 **옆에 전용 창**으로 뜹니다.
문서 · 표 · 코드 · 웹페이지 · 그림 · 계산기가 대상이고,
**15줄이 넘고, 따로 떼어 써도 말이 되고, 나중에 다시 볼 만한 것**이면 자동으로 만들어집니다.

| 할 수 있는 것 | 어떻게 |
|---|---|
| 버전을 넘나든다 | 이전 버전으로 되돌릴 수 있습니다 |
| 그 자리에서 고친다 | 고칠 부분을 드래그해 `Edit with Claude` |
| 그대로 꺼낸다 | 코드 보기 · 복사 · 내려받기 |

**자주 놓치는 것** — 대화에서 만든 아티팩트는 목록에 자동으로 올라가지 않습니다.
열어서 **`Publish`** 를 눌러야 남습니다. 오류가 나면 `Try fixing with Claude` 를 누르면 됩니다.

### 아티팩트는 두 종류입니다

| | 채팅 아티팩트 | Cowork 라이브 아티팩트 |
|---|---|---|
| 성격 | 만든 그때 그대로 고정 | **열 때마다 새로 채워집니다** |
| 어디에 남나 | 대화 안 | 사이드바 목록에 계속 |
| 버전 | — | 고칠 때마다 이전 버전 저장 |
| 요금제 | **무료도 됩니다** | **Pro 이상 · 데스크탑 전용** |

라이브 아티팩트는 아침 브리핑 · 현황 추적판 · 관심 대상 감시 같은 데 씁니다.

**붙일 커넥터는 하나뿐입니다.** 시세도 순위도 차트도 뉴스도 전부 그 하나에서 나옵니다.

**PlayMCP 는 커넥터 목록에 이미 등록돼 있습니다.** 주소를 복사해 붙일 일도, 설정 파일을 열 일도 없습니다.

두 도구 모두 **API 키를 넣는 칸이 없습니다.** 담기만 하면 바로 씁니다.

**선택이 둘 더 있습니다.** `duckdb`(호별 실제 공시가격 조회) · `powerpoint`(열려 있는 PPTX 잠금 해제).

## 미리 알아두실 것

> 📄 교재 PDF **p.96~97** — 공시가격은 가정값 · 마지막 장이 결론입니다

**공시가격은 감정평가액의 60%로 가정합니다.**
주택 공시가격을 개인이 조회할 수 있는 공개 API가 없기 때문입니다.
정확한 값이 필요하면 [부동산공시가격알리미](https://www.realtyprice.kr) 에서 확인해 알려주세요.
알려주면 즉시 다시 계산합니다.

**종부세는 낙찰 다음 해가 첫 과세연도입니다.**
과세기준일이 매년 6월 1일이라, 6월 이후에 잔금을 내면 그 해 종부세는 없습니다.
그래서 현행 세율이 아니라 **다음 해 세율**로 계산합니다.
2026.08.03 재정경제부 세제개편안 기준이며 **국회 통과 전 정부안**입니다.

**입찰 금액은 스킬이 정해주지 않습니다.**
STEP 7 「입찰 상한선」에서 저감률과 유찰 회차로 다음 기일 최저매각가격을 확인하고,
총 소요자금으로 상한선을 그어 **범위만** 제시합니다.
그 사이에서 얼마를 쓸지는 법원경매정보·온비드의 인근 낙찰사례를 직접 대조해 본인이 정하는 것입니다.

**낙찰 뒤 명도는 별도 스킬로 다룹니다.**
물건카드는 명도가 얼마나 어려울지(상/중/하)까지만 판정합니다.
낙찰된 뒤에 `낙찰됐어. 명도 계획 만들어줘` 라고 하면 **낙찰 후 명도** 스킬이
인도명령·강제집행 문서와 일정표를 만들어 줍니다.

**산출물은 PPTX 한 부뿐입니다.**
같은 물건을 다시 분석해도 그 파일 하나를 덮어씁니다 (백업은 `백업\` 에 남습니다).
PDF·이미지 같은 다른 형식은 폴더에 남기지 않습니다.

**민간 추정시세는 쓰지 않습니다.**
국토교통부 실거래가만 씁니다. 경매정보 사이트의 AI 추정가도 쓰지 않습니다.

**물건카드를 남에게 보내지 마세요.** 임차인 정보가 들어 있습니다.

> 이 도구는 판단 재료를 모아줄 뿐 대신 결정하지 않습니다.
> 실제 입찰 전에는 등기부·매각물건명세서 원문과 전문가 확인이 반드시 필요합니다.
> 특정 물건의 입찰을 권유하지 않으며, 투자 판단과 그 결과는 본인 책임입니다.
