# Post-Auction Eviction (직접 경매 낙찰 후 명도 자동화)

## 1. 스킬의 목적과 적용 시점

이 스킬은 **사용자가 경매 물건을 직접 낙찰받은 후** D+7 ~ D+90 기간의 명도 절차를 통합 자동화한다.

[확정] 적용 트리거 (다음 중 하나라도 해당):
- 사용자가 낙찰일·사건번호와 함께 명도/인도명령/강제집행 관련 문의
- 입찰 전 분석 스킬(`small-building-auction`, `residential-auction`, `commercial-unit-auction`, `land-auction`) 워크플로우가 GO 판단 → 낙찰 완료 → 명도 단계로 넘어간 시점
- 점유자 협상·합의서·소송 관련 문서 요청

[확정] 적용 제외:
- NPL 채권 매입 분석 (이 배포본의 범위가 아니다)
- 입찰 전 권리분석 (위 4개 입찰 분석 스킬로 분기)
- 잔금납부·취득세 신고 (별도 절차)
- 임대차 계약·임대수익 모니터링 (별도 워크플로우)

## 2. 표준 워크플로우 — 7단계

낙찰일을 D+0으로 정의하고 다음 순서로 진행한다.

```
Stage 1: Intake & 사건정보 수집           → D+0 ~ D+7
Stage 2: 점유자 유형 판정 (5개 시나리오)   → D+7 ~ D+10
Stage 3: D+N 마일스톤 자동 계산            → 즉시 산출
Stage 4: 1차 문서 생성 (인도명령·내용증명) → D+7 ~ D+14
Stage 5: 점유자 대응 분기 (협상/소송/집행) → D+14 ~ D+60
Stage 6: 2차 문서 생성 (강제집행·합의서)   → D+30 ~ D+90
Stage 7: 산출물 패키지 (MD+DOCX+XLSX)      → 각 단계마다
```

각 단계의 상세 절차는 아래 섹션에서 다룬다. 점유자 시나리오 분기 판정은 반드시 `references/occupant-scenario-decision.md`를 읽고 진행한다.

## 3. Stage 1 — Intake & 사건정보 수집

[확정] 사용자에게서 다음 정보를 우선 수집한다. 부족하면 명시적으로 질문한다.

**필수 입력**
1. 사건번호 (예: 2024타경12345)
2. 낙찰일 (매각허가결정일이 아닌 **매각결정기일**)
3. 매각허가결정 확정일 (불복기간 종료 후)
4. 잔금납부일 (없으면 매각허가결정 확정일 + 30일 추정)
5. 물건 유형 (주거용/상업용/토지)
6. 물건 소재지 (관할 법원 확정용)
7. 점유자 정보 (채무자 본인/임차인/유치권자 주장자/제3자)

**선택 입력**
- 매각물건명세서 PDF (점유자 정보 추출용)
- 등기부등본 (가등기·가처분 등 추가 권리 확인)
- 감정평가서 (월세 상당액 산정용)
- 임대차 계약서 사본 (대항력 판정용)

[확정] **MCP 활용**: 사용자가 사건번호만 제공한 경우 `court-auction` MCP의 `get_case_detail`을 호출하여 매각결과·매각기일·물건정보를 자동 추출한다. 호출 후 사용자에게 결과를 보여주고 누락 정보를 질문한다.

## 4. Stage 2 — 점유자 유형 판정 (5개 시나리오)

[확정] 점유자 대응 전략은 점유자 유형에 따라 완전히 달라진다. 다음 5개 시나리오 중 정확히 하나를 판정한다(중첩 가능 시 우선순위 적용).

| 시나리오 | 식별 지표 | 적용 절차 |
|---|---|---|
| **A. 일반 채무자/소유자 점유** | 매각물건명세서에 임차인 없음, 채무자 본인 점유 | 인도명령 → 강제집행 (가장 간단) |
| **B. 명도합의 우선 (이사비 협상)** | 점유자가 협조적, 단기 자진 이주 의사 | 합의서 → 이사비 지급 → 자진 이주 |
| **C. 대항력 있는 임차인** | 전입신고+점유 시기가 최선순위 근저당보다 빠름, 보증금 미배당 | 인도명령 불가 → **명도소송** + 보증금 인수 검토 |
| **D. 배당받은 임차인** | 배당요구 했고 보증금 전액 배당 | 인도명령 가능 (배당 후 인도 의무) → 강제집행 |
| **E. 유치권 주장자** | 매각물건명세서에 유치권 신고, 공사대금 등 주장 | 진위 판정 → 유치권 부존재확인소송 또는 협상 |

[확정] 판정 절차는 반드시 `references/occupant-scenario-decision.md`를 읽고 따른다. 잘못된 판정 시 **인도명령 vs 명도소송 선택 자체가 어긋난다**.

[확정] 시나리오 C/E는 법적 리스크가 크므로, 스킬은 1차 문서를 생성하되 **반드시** 사용자에게 "법무사·변호사 검토를 거친 후 제출 권장" 경고를 산출물에 포함한다.

## 5. Stage 3 — D+N 마일스톤 자동 계산

[확정] `scripts/calculate_milestones.py`를 실행하여 낙찰일 기준 키 마일스톤을 자동 계산한다. 입력은 낙찰일(YYYY-MM-DD) 1개이며, 출력은 다음 표 형태다.

| 단계 | 기준일 | 법적 근거 / 실무 관행 | 산출물 |
|---|---|---|---|
| 매각허가결정 확정 | D+14 | 민사집행법 §128 (1주 항고기간 + 결정송달) | — |
| 잔금납부 기한 | D+14 ~ D+44 (매각허가확정 + 30일) | 민사집행법 §142 | 자금조달 시뮬레이션 |
| **소유권이전등기** | 잔금납부 직후 | — | 등기촉탁 신청 |
| **인도명령 신청기한** | 잔금납부일 + 6개월 이내 | 민사집행법 §136①, ② | 인도명령신청서 |
| 1차 내용증명 발송 | D+14 (잔금납부 직후) | 협상 개시용 (실무 관행) | 내용증명 |
| 점유자 협상 시한 | D+30 | 합의 가능성 판단 분기점 | 합의서 또는 강제집행 결정 |
| 강제집행 신청 | D+45 (협상 결렬 시) | 인도명령 결정 후 즉시 가능 | 강제집행신청서 |
| 부당이득반환 기산 | 잔금납부일부터 | 민법 §741 (사용이익) | 청구 시 산정 |
| 명도 완료 목표 | D+90 | 실무 표준 | — |

[검증필요] 위 일정 중 "인도명령 신청기한 6개월"은 민사집행법 §136 조항이지만, 사용자 의사결정 전 반드시 공식 출처 확인 후 사용 권장 (국가법령정보센터).

[확정] 스크립트 실행 결과는 XLSX 일정관리 파일의 첫 시트 "마일스톤"에 기록된다.

## 7. Stage 7 — 산출물 패키지

[확정] 모든 워크플로우 종료 시 다음 3개 파일을 `/mnt/user-data/outputs/`에 생성한다.

1. **`{사건번호}_명도체크리스트.md`** — 단계별 체크리스트, D+N 일정, 점유자 시나리오 판정 결과, 리스크 경고
2. **`{사건번호}_명도일정관리.xlsx`** — 4개 시트
   - 시트 1: 마일스톤 (D+N 자동 계산)
   - 시트 2: 문서 생성 이력
   - 시트 3: 점유자 커뮤니케이션 로그 (날짜·수단·내용)
   - 시트 4: 비용 트래커 (송달료·이사비·강제집행비·소송비)
3. **`{사건번호}_명도문서패키지/`** (폴더) — 시나리오별 DOCX 문서들

XLSX 생성은 `xlsx` 스킬 가이드(`/mnt/skills/public/xlsx/SKILL.md`)를 먼저 읽고 진행한다. DOCX 생성은 `docx` 스킬 가이드(`/mnt/skills/public/docx/SKILL.md`)를 먼저 읽고 진행한다.

## 8. 사실 확신도 표기 규칙 준수

[확정] 이 스킬이 생성하는 모든 산출물은 사용자 환경설정의 **확신도 라벨 규칙**을 따른다.

- 법령 조항·기한·인지액은 **[검증필요]**로 표시하고 "공식 출처 확인 후 사용" 문구 병기
- 사건번호·금액·당사자명은 사용자 입력값이므로 **[확정]**으로 표시
- 정황 추정(예: 점유자 의사 추측)은 **[추정]**으로 표시

법령 인용 시 출처는 다음 우선순위로 확인:
1. 국가법령정보센터 (`korea-law-search` MCP)
2. 대법원 종합법률정보 (`korea-law-search` MCP의 case_research)
3. web_search/web_fetch (위 MCP 미사용 시만)

## 9. 다른 스킬과의 연계

[확정] 이 스킬은 다음 워크플로우의 후속 단계로 호출된다.

```
small-building-auction (입찰 전 GO 판단)
  ↓ 낙찰 완료
잔금조달 시나리오 (이 배포본 범위 밖)
  ↓ 잔금납부 완료
취득세 신고 (이 배포본 범위 밖)
  ↓ 소유권이전등기 완료
[현재 스킬: post-auction-eviction] (D+7 ~ D+90 명도)
  ↓ 명도 완료
(임대차 계약 / 매각 출구전략 — 별도 워크플로우)
```

[확정] 점유자 시나리오 C(대항력 있는 임차인) 또는 E(유치권 주장)로 판정된 경우, 명도 외에 **법령·판례 검색이 필요**하므로 `korea-law-search` MCP의 `case_research`를 병행 호출한다.

## 10. 산출물 톤 & 문서 품질 기준

[확정] 모든 법률 문서는 다음 기준을 준수한다.

- 한글 전문 용어 사용 (예: "점유" not "차지", "인도" not "건네줌")
- 당사자 표시 정확성: 신청인(낙찰자) / 피신청인(점유자) 구분
- 사건번호·법원명 정확 기재 (사용자 입력 검증)
- 송달주소 명시 (등기부 주소 + 실거주 주소 분리)
- 청구취지·청구원인 구조 (소장 형식)
- 별지 첨부 명시 (등기부등본·매각허가결정 정본 등)

[확정] 완성본 문서 하단에는 반드시 다음 경고문을 포함한다:

> ⚠️ 본 문서는 자동 생성된 초안입니다. 제출 전 다음을 확인하세요:
