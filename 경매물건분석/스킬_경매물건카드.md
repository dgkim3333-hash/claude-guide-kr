# 경매 물건카드 — 직접 낙찰 종합 분석

법원경매 서류를 받아 **입찰 판단에 필요한 것 전부**를 순서대로 확인하고 **PPTX 물건카드 1부**를 낸다.
NPL 채권 매입가 산정이 아니다.

> 확신도 라벨(`[확정]`/`[검증필요]`/`[추정]`/`[정보부족]`), 국토교통부 실거래가만 사용,
> 원화 원 단위 풀 콤마 표기는 사용자 개인 설정을 따른다.

## ★★ [정보부족] 게이트 — 라벨을 붙이기 전에 반드시 통과시킨다

`[정보부족]`은 **"확인할 수 없었다"**는 뜻이지 **"안 했다"**는 뜻이 아니다.
이 라벨을 쓰려는 순간, 아래 세 질문에 먼저 답한다.

```
1. 내가 가진 MCP·도구로 3~4번 호출 안에 확인되는가?
   → 예: 지금 호출한다. 라벨을 붙이지 않는다
2. 사용자가 파일 하나만 올리면 해결되는가?
   → 예: [정보부족]으로 두되 「확인해야 할 것」에 올리고, 무엇을 올리면 되는지 한 줄로 적는다
3. 어느 쪽도 아닌가? (기관이 제3자에게 공개하지 않는 정보 등)
   → 그때만 [정보부족]이고, 왜 못 얻는지 사유를 함께 적는다
```

**대표적인 실패 유형** — 「역세권 · 인근에 지하철 있음(감정평가서 기재) —
정확한 도보거리 미측정 `[정보부족]`」이라고 적고 넘어가는 것.
지오코딩 1번 + 도보경로 3번이면 끝나는 일이다.
**공백을 알아채고 라벨까지 붙였으면서 메우지 않은 것**이 문제다.
배점표에 「입지·교통 25점」이 있는데 재는 절차가 없으면 이런 일이 반복되므로
STEP 5-B 로 절차를 못박았다.

**실패 사례 (2026-08-27, 강사 실측)** — 「개별주택가격은 전국 통합 자료가 없다」는 한 줄을 믿고
공시가격을 가정으로 넘겼다. 실제로는 부동산공시가격 알리미(realtyprice.kr)에서 로그인·캅차 없이 개별 조회된다.
가정치가 실측의 1.55배였고 보유세 결론이 통째로 뒤집혔다.
**「자료가 없다」는 서술을 만나면 그것이 「통합 다운로드가 없다」인지 「조회가 안 된다」인지 가른다.**

이 게이트는 지하철뿐 아니라 **모든 항목에 적용된다.**

## STEP 0 — 서류를 눈으로 읽는다

### 텍스트 추출을 믿지 마라

경매정보 사이트 출력물과 스캔 등기부는 **텍스트 레이어에 숫자가 없다.**
`청구액 원`, `억 만원` 처럼 숫자만 빠진 채 뽑힌다. 그대로 넘기면 **금액을 지어낸다.**

```
1. pypdfium2 로 페이지를 이미지로 렌더링 (scale=2.0)
2. Read 도구로 PNG 를 한 장씩 열어 눈으로 읽는다
3. 30장이 넘으면 서브에이전트에 넘기되
   "bash 로 텍스트를 뽑지 말고 PNG 를 열어 읽으라"고 명시한다
```

### 서류 우선순위

| 서류 | 없으면 |
|---|---|
| **매각물건명세서** | 임차인·인수 판정 불가 → 분석의 절반이 날아간다 |
| **현황조사서** | 실제 점유 파악 불가 |
| **전입세대열람** | 전입일 확정 불가. 있으면 대항력 판정이 3중으로 닫힌다 |
| **감정평가서** | 가격 근거·규제·주변환경 공백 |
| 등기사항전부증명서 (토지·건물 각각) | 말소기준권리 판정 불가 |
| 건축물대장 | 면적·용도·위반건축물 확인 불가 |
| 문건/송달내역 | 절차 동향·저항 강도 파악 불가 |
| 경매정보 (사설) | 보조. **여기 실린 추정시세는 쓰지 않는다** |

**토지 등기부가 빠지는 일이 잦다.** 반드시 지적한다.
파일명은 관대하게 본다 (`법원물건접수`/`법원문건접수`, `물건명세서`/`매각물건명세서` 동일 처리).

## STEP 1 — 문건/송달 타임라인 (본 분석보다 먼저)

날짜 / 접수자 / 내용 / **읽는 법** 4열. 해석을 반드시 붙인다.

### 채무자 저항 지수 (0~10)

0~2 무대응 · 3~5 일반 대응 · 6~8 적극 방어(변호사·재감정) · 9~10 강력 저항(항고·소송)
6점 이상이면 회수 기간을 보수적으로 잡는다.

### ★ 기일 변경·연기의 주체를 반드시 본다

| 주체 | 의미 | 입찰자에게 |
|---|---|---|
| 채무자 | 시간 벌기·변제 협의 | 취하 가능성 |
| **채권자 (근저당권자·NPL 양수인)** | **가격 하락 방어** | **다음 기일도 안 열릴 수 있다** |
| 법원 | 절차 하자 보정 | 대체로 재개 |
| 임차인 「경매속행 신청」 | 배당을 빨리 받으려는 것 | 채권자와 충돌 중 |

「경매유예정지협조요청」·「매각기일연기신청」이 채권자 명의면 **의도적으로 멈춘 것**이다.
**입찰 전 해당 계에 기일 진행 여부를 직접 확인**하라고 쓴다.
배당 슬라이드에서 **채권자 회수율**을 시나리오별로 계산하면 그 동기가 숫자로 드러난다.

### 이해관계인 지도

**근저당권 이전(확정채권양도)**이 있으면 양수인을 적는다 — 대응 상대가 바뀐다.
가압류 채권자가 **그 건물의 시공사**면 공사대금 미지급 정황이다. 건축물대장 공사시공자란과 대조한다.

★ **등기명의인표시경정은 채권자 변경이 아니다.** 오기 정정일 뿐이므로 대응 상대가 그대로다.
승계집행문 부여·근저당권 이전(확정채권양도)·당사자변경과 혼동하지 마라.

## STEP 2 — 권리 순위와 말소기준

토지와 건물의 최선순위 설정일이 다를 수 있다. 매각물건명세서 「최선순위 설정」란에 목록별로 적혀 있으면 그대로 쓴다.
**토지 등기부가 없으면 건물 기준으로만 표를 만들고 그 사실을 밝힌다.**

> **접수번호를 대조하라.** 건물·토지 각 필지의 근저당 접수번호가 같으면 동시 설정이고
> 말소기준일이 일치한다. 번호가 다르면 필지별로 기준일을 따로 잡아야 한다.

### ★ 신축 물건의 선순위 임차인 가능 구간

건물에 전입할 수 있는 **최초일 = 사용승인일**이다. 사용승인일과 건물 근저당 설정일 사이가 **대항력이 생길 수 있었던 창**이다.

```
사용승인 2023.09.25 → 소유권보존 2023.10.30 → 근저당 2023.10.30
→ 창은 2023.09.25 ~ 10.29, 약 1개월
→ 그 기간 전입자가 있는지만 확인하면 끝난다
```

말소된 등기는 취소선으로 따로 모은다 — **지워졌어도 그런 일이 있었다는 사실은 남는다.**

## STEP 3 — 인수·소멸 판정

### 매각물건명세서가 먼저다

| 명세서 란 | 읽는 법 |

| 「매각으로 그 효력이 소멸되지 아니하는 것」 | **공란이면 인수 없음** — 법원이 확인해 준 것 |
| 「매각에 따라 설정된 것으로 보는 지상권」 | 기재가 있으면 법정지상권 성립 |
| 비고란 | 일괄매각·제시외 포함·특별매각조건 |

보증금 미상 / 상가 임차인 / 근생 1종·2종 / 공부상 용도 vs 현황 / 위반건축물 / **제시외 건물** / 유치권 /
법정지상권 / **담보지상권** / 지분 경매 / 일부 지분 물상보증 / 공동담보 / 중복·병합 / 채무자=소유자 /
**채권자 변경** / 채무자 파산·회생 / 기록열람신청 / 체납 관리비

**담보지상권**(근저당과 같은 날 설정된 지상권)은 근저당이 소멸하면 함께 소멸한다.

## STEP 4 — 임차인 개별 분석

표 1행 = 임차인 1명.
점유부분 / 전입일 / 확정일자 / 보증금·차임 / 배당요구 / 대항력 / **최우선변제액** / 예상 배당 / **미배당 잔액**

### 임차인이 없을 때도 표로 보여준다

「임차인 없음」은 결론이지 생략 사유가 아니다. **어느 서류가 각각 무엇으로 확인해 줬는지** 표로 남긴다.
매각물건명세서 / 현황조사서 / 전입세대열람 / 문건접수내역 네 가지가 서로 맞아떨어지는지 대조한다.

### 전입세대열람이 있으면 반드시 최선순위 설정일과 대조한다

전입일이 최선순위 설정일보다 **빠르면** 형식상 선순위다.
소유자 본인일 가능성이 높으면(등기 주소변경일과 일치, 현황조사서에 「채무자겸소유자 세대」 기재)
그렇게 해석하되, **전입세대확인서의 성명이 마스킹이라 문서만으로는 동일인 확정이 불가**함을 명시하고
현장 확인을 요구한다.

### ★ 임차권등기가 있으면 명의를 본다

임차권등기명령에 의한 등기가 **개인 본인 명의 그대로**인지, **HUG·HF 등 보증기관으로 이전(부기등기)**됐는지
확인한다. 이전 부기등기가 있으면 보증기관이 대위변제한 것이다.

- **인수 부담은 그대로 0원이다.** 대위변제자는 임차인의 지위를 승계할 뿐 없던 대항력이 생기지 않는다
- **바뀌는 것은 명도다.** 보증기관은 대위변제 조건으로 퇴거·임차권 이전을 요구하므로 그 호실은 이미 비었거나 협상이 수월하다
- 임차권등기를 한 임차인은 **대항요건을 유지한 채 이사 갈 수 있다** — 이미 비웠는지 현장 확인이 필요하다
- 대위변제는 **배당요구 종기 후에도 발생**한다. 입찰 직전 문건접수·등기부를 다시 본다

### 배당을 못 받는 임차인은 명도가 어렵다

대항력이 없어 인수 부담이 0이어도 **보증금을 통째로 잃는 임차인은 순순히 나가지 않는다.**
반대로 **최우선변제로 전액을 받는 임차인은 명도가 수월하다.** 이 구분을 표에 적고 이사비 예산에 반영한다.
단, 전액을 받으면서도 임차권등기까지 한 임차인은 **절차를 아는 상대**이므로 난이도를 한 단계 올린다.

### 당해세 안분

문건접수내역에 「국세·지방세 안분적용신청서」나 법원의 「통지서(안분적용)」가 있으면
**배당표가 아직 굳지 않았다.** 반드시 본문에 적는다.

## ★★ STEP 4-C — 대항력 임차인 vs 선순위 조세 (법정기일 게이트) (2026-10-02 신설)

**이 절이 이 규칙의 정본이다.** `priority-payment-date-rule` 은 이 절을 요약해 참조한다.

**실패 사례 (2026-10-02, 강사 실측 사례 — 공매 물건)** —
임차인 대항력·우선변제 기준일보다 2~3개월 뒤에 세무서 압류 등기가 있었다.

조세 순위는 압류 등기일이 아니라 **법정기일**로 정해지고, 압류는 법정기일보다 한참 뒤에 한다.

### 판정 규칙 (2026-10-02)

1. **임차인 기준일 T 이후에 등기·접수된 조세 압류·교부청구가 하나라도 있으면**, 간격과 관계없이 **법정기일을 확인하기 전까지 임차인보다 선순위로 가정**한다.
2. **압류·교부청구일 − T ≤ 6개월 → 「고위험」** 으로 표시한다. 독촉→압류 절차상 법정기일이 T보다 앞설 가능성이 매우 높다.
3. **6개월을 넘어도 「안전」으로 판정하지 않는다.** 압류는 법정기일보다 수년 뒤에 하는 일이 흔하다. 「주의」로 두고 1번을 그대로 적용한다.
4. T **이전**에 등기된 조세 압류는 당연히 선순위다.
5. 금액·법정기일을 확인하기 전의 선순위 조세는 **X `[정보부족]`** 로 둔다. **X = 0원으로 채워 배당표를 완성하지 않는다.**

### 반드시 낼 것

- **배당표**: 「선순위 조세 X (법정기일 미확인)」 행을 **임차인 앞에** 넣는다.
- **바닥 총투입**: 대항력 임차인이 있으면 낙찰가가 내려간 만큼 인수 보증금이 늘어, 총투입이
  `보증금 + 집행비용 + 당해세 + X + 취득세 등 + 부대비용` 에서 멈춘다. **낙찰가를 낮춰도 X는 그대로 남는다.**
- **X 민감도 표**: X = 0원 / 인수 시작점 / **손익분기 X** / 100,000,000원 / 200,000,000원 / 300,000,000원 — 각 행에 바닥 총투입과 추정 시가 대비 여유.
- **손익분기 X** = 바닥 총투입이 추정 시가와 같아지는 X. 이보다 크면 「어떤 낙찰가도 손실」.
- **결론 첫 장**: 「X 확인 전 입찰 금지 — 판단은 본인」을 쓴다. 결론 문장 뒤에 묻지 않는다.
- **「선순위 조세(국세 재검토)」 슬라이드 필수** — 법리 표 + X 민감도 표.

## ★ STEP 5-B — 지하철 접근성 (배점표에 「입지·교통 25점」이 있으므로 반드시 잰다)

**역명만 적고 거리를 생략하지 마라.** 감정평가서는 대개 「인근에 지하철이 소재하는 등 교통상황은 보통임」
이라고만 쓰고 거리를 밝히지 않는다. **그 문장으로 25점을 매기지 마라.** 도구 호출 4번이면 실측된다.

### 5-B-1. 물건 좌표

```
mcp__vworld-landuse__geocode_address(address="<지번주소>")   → {x: 경도, y: 위도}
```

동·호수는 떼고 지번까지만 넣는다. 실패하면 도로명↔지번을 바꿔 재시도한다.

### 5-B-2. 역 후보 수집 — 2회 검색

```
KakaoMap-SearchPlaceByKeywordOpen(keyword="<시군구> <읍면동> 지하철역")
KakaoMap-SearchPlaceByKeywordOpen(keyword="<시군구> 기차역")        ← KTX·SRT·광역철도
```

카테고리로 종류를 판정한다. `교통,수송 > 지하철,전철 > <노선명>` = 지하철 /
`교통,수송 > 기차,철도 > 기차역 > KTX정차역` = 고속철.
한 역이 양쪽에 잡히면 하나로 합치고 노선을 둘 다 적는다 (예: `7호선 · 경의중앙선 · KTX`).

### ★★ 5-B-2-1. 건설 중·계획 노선을 반드시 조회한다 (2026-10-03 신설)

**카카오맵은 공사 중인 역을 보여주지 않는다.** 5-B-2 검색만으로는 운영 중인 역만 잡힌다.
「카카오 미검색」은 「역 없음」이 아니다. 이 문구로 `[검증필요]`를 붙이고 넘어가지 않는다 — **[정보부족] 게이트 1번(3~4회 조회로 확인되는가)에 해당한다.**

**실패 사례 (2026-10-03, 강사 실측 사례)** — 입지 조사가 「건설 중 노선의 인근 예정역 카카오 미검색 [검증필요]」라고 보고했는데 그대로 해설 한 줄로 넘겼다.
같은 노선의 **(가칭)○○역이 같은 동에서 공사 중**이었고, 물건에서 직선 455m(도보 617m)였다 — 등급이 「준역세권」에서 개통 후 「초역세권」으로 바뀌는 사안이었다. 강사가 보고서를 받은 뒤 지적했다.

**조회 순서 (모두 공식 출처)**

1. `WebSearch` — `"<시군구> <읍면동> 복선전철 OR 도시철도 OR 광역철도 정거장"`, `"<시군구> 철도 건설 정거장 위치"` (`allowed_domains`: kr.or.kr · molit.go.kr · 시청·도청 도메인 · korea.kr)
2. **지자체 철도 사업 페이지** (예: ○○시청 「광역전철」 메뉴) — 노선·정거장 이름·공구·시공사·착공·개통 목표
3. **국가철도공단 사업실명제 공시**(kr.or.kr 사업실명제 게시판, hwpx 첨부) — 사업기간·실시계획 승인 고시번호
4. **정거장 위치** — 공식 도면·고시가 없으면 단서(위키 등)의 지번을 `vworld-landuse geocode_address` 로 좌표화하고, `get_land_use_plan`·`get_parcel_info` 로 지목(도로 밑 지하역이면 「도」)을, `KakaoMap-GetWalkDirections` 의 목적지 해석(교차로명)으로 정황을 맞춘다. **위키는 근거가 아니라 단서다** — 위치는 공식 확인 전까지 `[검증필요]`
5. 직선·도보거리를 5-B-3·5-B-4 와 같은 방식으로 잰다

**표기 규칙**

- 지하철 표에 **「상태」 열**을 두고 `운영` / `공사 중` / `계획(미착공)` 을 구분한다
- 등급은 **「현재 / 개통 후」 두 시점**을 함께 적는다. 종합 점수의 「입지·교통」은 현재 기준, 개통 효과는 「미래가치」에서 반영한다
- 개통 목표가 출처마다 다르면(예: 공단 2028 / 시 2029) **둘 다** 적는다. 공구·시공사 불일치도 그대로 적는다
- **개통 후 매각을 출구로 볼 때는 보유 기간의 기회비용과 보유세를 넣은 「기다림의 손익분기 프리미엄」 표를 낸다.** 프리미엄 크기는 근거 수치가 없으면 `[가정]` 민감도로만 낸다
- 5-B-8 그대로 — 개통 예정으로 낙찰가율 계수를 올리지 않는다
- 착공 전 「계획」 노선(예비타당성·기본계획 단계)은 표에 넣되 등급 산정에서 뺀다 — 무산·지연 이력이 흔하다

### 5-B-3. 거리는 직접 계산한다 ★

**카카오맵은 거리순으로 정렬해 주지 않는다.** 시군구 전체의 역을 반환한다.
검색 순서를 가까운 순으로 착각하면 안 된다.

1. 각 역 주소를 `geocode_address`로 좌표 변환
2. 물건 좌표와 **직선거리(haversine)** 계산
3. 가까운 순 정렬 → **지하철 상위 3개**를 표에 넣는다

```python
from math import radians, sin, cos, asin, sqrt
def km(p, q):
    (x1, y1), (x2, y2) = p, q          # (경도, 위도)
    x1, y1, x2, y2 = map(radians, [x1, y1, x2, y2])
    return 2*6371*asin(sqrt(sin((y2-y1)/2)**2 + cos(y1)*cos(y2)*sin((x2-x1)/2)**2))
```

★ **역 중심 좌표가 아니라 실제 출입구 좌표를 쓰면 거리가 달라진다.** 도보경로 API가 돌려주는
종점 좌표가 출입구이므로, 도보를 먼저 부르고 그 좌표로 직선거리를 다시 재면 정밀해진다.
실측에서 역 중심 기준 1,096m 였던 역이 출입구 기준 578m 로 바뀌어 등급 판정이 달라졌다.

### 5-B-4. 3km 이내만 도보 병기

```
KakaoMap-GetWalkDirections(origin="<지번주소>", destination="<역명>", routeMode="SHORTEST_TIME")
```

- **3km 초과** — 직선거리만 적고 도보경로를 호출하지 않는다
- **3km 이내** — 실제 도보 거리·시간을 병기한다 (초 단위 응답을 분으로 반올림)

### 5-B-5. 역세권 등급

| 최근접 역 직선거리 | 등급 |
|---|---|
| 500m 이내 | 초역세권 |
| 500m ~ 1km | **역세권** |
| 1 ~ 3km | 준역세권 (도보 병기) |
| 3 ~ 10km | 비역세권 — 차량 접근 |
| 10km 초과 | **지하철 접근성 없음** |

### 5-B-6. KTX·SRT·광역철도는 표가 아니라 해설에 적는다

정차역이 **있다는 사실만으로 호재로 적지 않는다.** 거리를 함께 밝히고,
도보 생활권이 아니면 그렇게 쓴다. 지하철 3개 표 아래 해설 박스에 한 줄로 붙인다.

### 5-B-7. 노선의 질도 본다

역 개수만 세지 마라. **단일 노선인지, 환승 없이 어느 업무지구에 닿는지**를 적는다.
7호선 단일이면 강남 직결은 되지만 도심(종로·시청)은 환승 1회다 — 임대 수요층이 한쪽으로 쏠린다.
이 판단은 `[추정]` 라벨을 단다.

### 5-B-8. 가격에 직접 반영하지 않는다

역세권 등급을 예상 낙찰가에 곱하거나 빼지 마라. 입지는 **「지하철 접근성」 슬라이드**와
**종합 점수의 「입지·교통 25점」**에만 쓴다. 가격은 STEP 5 시세와 STEP 7 상한선으로 본다.

### 당해세 판정

- **갑구의 압류**에서만 판정한다. **토지·건물 각각 확인한다** — 한쪽에만 있는 경우가 흔하다.
- 소재지 최소 행정단위(구·면)와 압류권리자 관할이 일치할 때 당해세.

- **세무서장 압류는 채무자가 법인일 때만 당해세.** 개인이면 일반 국세다.
- 등기부 금액 표기는 **천원 단위** (`3158` → 3,158,000원).
- 교부청구서가 있으면 압류 등기의 처분청과 대조한다. 일치하면 당해세 판정이 닫힌다.
- **교부청구서에 「당해세계」 란이 있으면 지자체가 스스로 당해세를 표시한 것이다** — 그 값이 가장 강한 근거다.

```
3. 차감 — 인수 보증금 · 명도비 · 취득세 · 명도 공백기 이자 · 수선비
```

**「상한 − 차감」이 입찰 가능한 최대치**다. 그 안에서 얼마를 쓸지는 경쟁 예측의 영역이고,
경쟁 예측은 근거 없이 하지 않는다.

**반드시 함께 적는다**

- 유찰 회차와 다음 회차 최저가 (「변경」·「연기」는 유찰이 아니다)
- 회차별 저감률은 **관할 법원 공고를 직접 확인**하라고 쓴다. 법원마다 다르다
- 인근 낙찰사례를 못 구했으면 `[정보부족]` 으로 두고 어디서 구하는지 한 줄로 적는다

**가정 낙찰가는 여기서 정한다 (2026-10-13 강사판 반영).** STEP 8(세금)·STEP 9(자금)·민감도·예상 배당에 쓰는
「가정 낙찰가」는 STEP 7 이 끝난 뒤 정하고, **이 장에 적힌 금액(최저매각가격 · 상한 − 차감) 중 하나이거나 사용자가 지정한 금액**만 쓴다.
어느 쪽인지(예: 「STEP 7 최저매각가격」 · 「사용자 지정」)를 그 장마다 적는다. 시세를 보고 따로 정한 금액을 여러 장에 퍼뜨리지 않는다 —
강사 실측 사례에서 스킬 밖 금액(예: 652,000,000원)이 세금·레버리지 장 전체에 퍼져 결론이 틀어졌다.

> 강사판은 이 자리에서 `auction-bid-price` 를 불러 「4단계 산정표」로 권장 입찰가를 내고 `bid_gate.py` 로 덱을 검사한다
> (이 교재에는 없음 — auction-guide-kr 에 있음). 이 판은 범위만 낸다.

**하지 않는 것**

- 통계 근거 없이 「이 정도면 될 것 같다」는 금액 제시
- 응찰자수·단독응찰 확률 추정

## 8-C. 종부세 과세대상 — 무엇에 매겨지나 (자주 틀리는 곳)

**「종부세는 건물에만 붙는다」는 흔한 오해다.** 조문은 이렇게 이어진다:

```
주택법 §2 1호 (MST 283191)
  "주택"이란 … 건축물의 전부 또는 일부 및 그 부속토지를 말하며
        ↓
지방세법 §104 3호 (MST 282559)
  "주택"이란 주택법 §2 1호에 따른 주택.
  이 경우 토지와 건축물의 범위에서 주택은 제외한다.
        ↓
종합부동산세법 §2 3호 (MST 280417)
  "주택"이란 지방세법 §104 3호에 의한 주택
```

→ **주택분 종부세는 건물 + 부속토지를 한 덩어리로 본다.** 개별주택가격·공동주택가격도 나누지 않고 하나로 공시된다.

**토지에도 별도로 종부세가 있다** (종부세법 §12·§13):

| 과세대상 | 근거 | 기본공제 |
|---|---|---|
| **주택** (건물 + 부속토지 일체) | §7·§8 | 개인 12억(개편안 거주 14억·비거주 9억) / 법인 0원 / 그 외 9억 |
| **종합합산 토지** (나대지·잡종지 등) | §12①1·§13① | **5억원** |
| **별도합산 토지** (상가·사무실 부속토지) | §12①2·§13② | **80억원** |
| **건축물 (주택 아닌 것)** | — | **과세대상이 아니다** |

- 주택 부속토지는 이미 주택분으로 과세되므로 토지분에서 제외된다. 이중과세 없음.
- **상가·오피스·공장 건물 자체는 종부세가 없다.** 부속토지만 별도합산 80억 초과 시 과세.
  → 상업용 물건에 주택분 세율을 쓰면 크게 틀린다.

### ★ 지역은 관계없다

**종부세법 §8① 의 공제액에는 지역 조건이 없다.** 전국 공시가격을 합산해 판정한다.
지방 아파트라도 공제액을 넘으면 과세되고, **법인은 공제 0원이라 지역·금액과 무관하게 첫 원부터 과세**된다.

「수도권 외 지역 1주택」 합산배제(§8②2호)는 조문에 남아 있으나 **2009.1.1~2011.12.31 납세의무 성립분에 한정**되어 이미 종료됐다. 살아 있다고 쓰지 마라.

지방이 유리한 것은 두 가지뿐이다:

| 특례 | 근거 | 내용 |
|---|---|---|
| 지방 저가주택 | §8④4호 + 시행령 §4의2③ | 공시가격 **4억원 이하** + 지정 지역이면 1주택자가 추가 보유해도 **1세대1주택자로 본다**. 단 **주택 수 판정에서만** 유리하고 과세표준에는 합산된다 |
| 공정시장가액비율 | 2026 개편안 `[검증필요]` | 조정대상지역·3주택 이상은 2028년 80%, 그 외는 70% |

## 8-D. 종부세 계산 순서 — 재산세 공제를 빠뜨리지 마라

```
① 주택 공시가격 합산 (건물 + 부속토지 일체)
② − 기본공제
③ × 공정시장가액비율          ← 해당 연도 값 (2027년 70% / 2028년 70~80%)
④ = 과세표준
⑤ × 세율                     ← 해당 연도 값
⑥ − 재산세 공제               ← 종부세법 §9③, 시행령 §4의3①
⑦ = 종부세
⑧ + 농어촌특별세 (종부세의 20%) `[검증필요]`
```

**⑥ 재산세 공제 계산식 (시행령 §4의3①)**

```
공제액 = 주택분 재산세로 부과된 세액의 합계액
       × (종부세 과세표준 × 재산세 공정시장가액비율 × 재산세 표준세율)
       ÷ 주택을 합산하여 주택분 재산세 표준세율로 계산한 재산세 상당액
```

**주택이 1채면 분자의 「재산세 부과세액」과 분모의 「재산세 상당액」이 같아 상쇄된다.** 결국:

```
공제액 = (종부세 과세표준 × 재산세 공정시장가액비율 60%) 에 재산세 주택분 표준세율을 적용한 금액
```

예: 과표 764,132,600원 → × 60% = 458,479,560원
→ 570,000 + (458,479,560 − 3억) × 0.4% = **1,203,918원 공제**

**이 공제를 빠뜨리면 종부세가 과다 산출된다.** 반드시 넣는다.

> ★ **주택·근생 복합이면 「안분된 주택분 과세표준」으로 공제액을 계산한다.**
> 안분 전 전체 금액으로 계산하면 공제액이 부풀려져 종부세가 과소 산출된다.
> 산출 후 `종부세 = 산출세액 − 공제액` 이 음수가 되면 계산이 틀린 것이다.

`다가구주택은 1주택으로 본다` (종부세법 시행령 §4의3③2)

시/군/구 콤보는 시/도를 고른 뒤 비동기로 채워지므로 선택 사이에 잠깐 기다린다.

- 브라우저 도구(Claude in Chrome 등)가 연결돼 있으면 직접 조회한다. 없으면 사용자에게 「알리미에서 조회해 개별주택가격·대지면적(산정)·기준연도를 알려 달라」고 요청하고, 답을 받기 전에는 아래 60% 가정으로 진행하되 결론 장에 「공시가격 미조회 — 보유세는 가정값」을 적는다.
- **결과 표에서 네 값을 전부 가져온다** — 개별주택가격(재산세·종부세 과세표준) · **대지면적(산정)**(지자체가 정한 주택 부속토지 면적, 나머지가 근생 부속토지) · 건물연면적(산정) · 가격기준연도.
- 여러 필지 위 1동이면 **대표 지번 하나에만** 등재된다. 다른 지번 0건은 정상이다.
- **실측 사례 (강사, 2026-08-27)** — 개별주택가격 588,000,000원인데 「감정평가액 × 60%」 가정치는 910,768,601원으로 1.55배였다.
  그 탓에 재산세 1세대1주택 특례세율(시가표준액 9억원 이하 한정)이 빠지고 개인 종부세가 「과세」로 나왔다 — 둘 다 뒤집혔다.
- (강사 환경 전용 — 강사는 vworld `get_house_price` API로 먼저 조회한다. 이 교재의 `vworld-landuse` MCP에는 이 기능이 없으므로 알리미를 쓴다.)

개별공시지가는 `vworld-landuse get_parcel_info` 로 확정할 수 있다(토지만).

#### 조회에 실패했을 때만 → **감정평가액 × 60%**

**조회를 시도하지 않고 바로 여기로 오지 마라.** 시도한 사실과 실패 사유를 함께 적고 `[추정]` 을 단다.

> **★ 2026-08-26 개정 — 종전 「감정평가액 × 50%」를 60%로 올렸다.**
> 실측 재산세 부과액에서 역산한 공시가격이 50% 가정치의 **1.5~1.9배**로 나오는 사례가 확인됐다.
> 50%는 보유세를 체계적으로 과소 산출한다. **60%가 유일한 기본값이고 50%는 더 이상 쓰지 않는다.**
> **「낙찰가 × 70%」 같은 방식도 쓰지 않는다** — 분모가 낙찰가면 회차마다 공시가격이 달라져
> 보유세가 낙찰가를 따라 움직이는 오류가 난다.
> **공시가격의 분모는 언제나 감정평가액이다. 낙찰가가 아니다.**
>
> 따라서 **낙찰가 시나리오를 여러 개 비교할 때 보유세 행은 전부 같은 값이어야 한다.**
> 시나리오마다 재산세·종부세가 달라지면 분모를 잘못 잡은 것이다.

**슬라이드 맨 위에 가정임을 크게 밝힌다:**

> ★ 공시가격 가정 — 감정평가액 × 60%
> 부동산공시가격 알리미 조회를 시도했으나 (사유)로 확인하지 못했습니다.
> 실제 값이 확인되면 즉시 다시 계산합니다.

건축물대장에 없는 **제시외 건물**은 공시가격 산정에 들어가지 않을 가능성이 크다 — 그 사실을 적는다.

### 2-A. ★ 교부청구서가 있으면 역산해 **검산만** 한다 — 조회 실패 시 보조 검산이다. 값을 대체하지 않는다

지자체 교부청구서에는 **실제 부과된 재산세 주택분 세액**이 실려 있다. 이것으로 공시가격을 역산할 수 있다.
그러나 **역산값을 기본값으로 채택하지 마라.** 아래 세 가지 이유로 유일해로 수렴하지 않는다.

**역산 절차**

```
세액 → (누진세율 역산) → 과세표준 → ÷ 공정시장가액비율 → 공시가격
  표준세율 : 6천만 0.1% / 1.5억 60,000+0.15% / 3억 195,000+0.25% / 3억초과 570,000+0.4%
  공정시장가액비율 : 주택 60% (지방세법 시행령 §109①2)
```

**역산을 믿으면 안 되는 이유**

| # | 문제 | 왜 유일해가 안 나오나 |
|---|---|---|
| 1 | **분기가 갈린다** | 「표준세율 + 공정시장가액비율 60%」와 「1세대1주택 특례세율(§111의2) + 45%」가 **같은 세액을 똑같이 재현**한다. 어느 쪽을 택하느냐에 따라 역산 공시가격이 1.5배 이상 벌어진다 |
| 2 | **교부청구서는 물건 단위가 아니라 채무자 단위다** | 개인지방소득세·주민세처럼 그 부동산과 무관한 세목이 섞여 있다. 재산세 주택분이 여러 건이면 다른 물건 것일 수 있다 |
| 3 | **세부담상한·조례 가감이 걸리면 역산 자체가 불가능** | 상한이 적용된 해의 세액은 세율 산식으로 되돌릴 수 없다. 지자체는 조례로 표준세율을 가감할 수 있다(지방세법 §111③) |

**그래서 이렇게 쓴다**

```
1) 공시가격 = 감정평가액 × 60%          ← 산출물에 쓰는 값은 언제나 이것
2) 교부청구서가 있으면 역산해 본다        ← 화면 밖 검산
3) 역산값 ÷ 가정값 이 1.3배를 넘거나 0.7배 미만이면
   → 슬라이드에 경고 박스를 띄운다. 값은 바꾸지 않는다
4) 역산값이 주택분 감정평가액을 넘으면 그 분기는 폐기한다 (공시 > 감정은 성립하지 않는다)
```

**경고 문구 (3에 해당할 때 그대로 쓴다)**

> 가정 공시가격과 실측 부과액이 어긋납니다. 20XX년 실제 재산세 본세는 OOO원인데
> 「감정평가액 × 60%」 가정으로 산출하면 OOO원입니다(실측의 OO%).
> 역산 공시가격은 약 OOO원으로 가정치의 O.O배입니다.
> 다만 교부청구서는 채무자 단위 체납이라 다른 물건의 세금이 섞여 있을 수 있고,
> 공정시장가액비율·특례세율 분기가 갈려 역산값을 확정치로 쓸 수 없습니다.
> **보유세를 보수적으로 보려면 실측 부과액을 기준선으로 쓰십시오. 개별주택가격 확인이 필요합니다.**

**역산 결과는 반드시 `[추정]` 라벨을 단다.** `[확정]`을 붙이지 마라.

### 3. 공시가격 DB 가 없으면 → **감정평가액 × 60%** 를 가정하고 반드시 밝힌다

주택 유형과 무관하게 같은 문구를 쓴다.

`2025.01.01 기준` 처럼 연도를 반드시 적는다. 연도를 안 쓴 공시가격은 쓰지 않은 것과 같다.

## 8-G. ★★ 주택·근생 복합의 안분 — 세목마다 기준이 다르다 (2026-08-27 전면 개정)

> 강사판의 정본은 `property-tax-apportionment` 스킬이다(이 교재에는 없음 — auction-guide-kr 에 있음). 아래 요약만으로도 계산할 수 있다.
> 종전 8-G의 「연면적으로 안분한다」는 **폐기됐다** — 연면적 안분은 신축·증축 취득 전용이다.

| 세목 | 근거 조문 | 안분 기준 |
|---|---|---|
| **취득세 (경매 등 승계취득)** | **지방세법 시행령 §19②** | **시가표준액 비율** |
| 취득세 (신축·증축) | 같은 조 §19③ | 연면적 비율 — 경매에는 쓰지 않는다 |
| **재산세 · 종합부동산세** | **지방세법 §106②1호** | **건물 면적비율** |

**두 값이 다른 것이 정상이다.** 같게 나오면 한쪽이 틀렸다.
실측 사례는 취득세 주택 57.50% / 보유세 주택 59.15% 로 갈렸다.

**§19② 분자에 개별주택가격을 넣지 마라** — 조문이 「건축물 중 주택 부분은 법 §4②」라고 못박았다.
건물 시가표준액은 용도지수(다가구 91 / 상점·사무소 112)와 가감산율(5~10층 건물 1층 상가 +17%)로
갈리고, 구조지수·위치지수·잔가율은 주택·근생 공통이라 상쇄된다.

**연면적에서 제외되는 옥탑 다락·계단실도 취득세 과세대상 건축물이다**(지방세법 §6 4호).
귀속은 8-E 2 알리미 결과의 대지면적(산정)으로 역산해(주택 부속토지 ÷ 대지 전체 = 비율 → 건물 전체 × 비율 = 주택분 건물면적, 건축물대장 항목 조합과 맞는지 확인) **지자체가 실제로 어떻게 나눴는지 먼저 확인**하고 맞춘다.

**근생 건물은 종부세 대상이 아니고 그 부속토지만 별도합산(8,000,000,000원 공제)**이다 — 8-C 참조.
안분된 주택분 전체에 주택 세율(개인 1~3% / 법인 12%)을, 근생분 전체에 4%를 적용한다.
**토지를 따로 떼어 전부 4%를 적용하면 크게 과소 계상된다.**
단독주택 1가구·근생 없음이면 안분이 필요 없다.

## 8-H. 개인·법인 두 경우를 나란히

지정이 없으면 **개인(무주택 → 1주택)** 과 **법인(다주택 보유)** 을 함께 낸다.
개편안에서는 개인 1주택이 **거주 14억 / 비거주 9억**으로 갈리므로 **둘 다 보여준다.**
취득세 격차는 한 번이지만 **보유세 격차는 매년 반복**된다 — 몇 년이면 취득세 격차를 넘는지 계산해 보여준다.

**공제액 경계에 가까우면 그 사실을 적는다.** 공시가격이 기본공제액에 조금 못 미치면
「공시가격이 몇 % 만 더 높아도 과세가 시작된다」를 계산해 함께 쓴다. 경계 부근에서는
공시가격 가정치가 조금만 틀려도 종부세가 0원과 수백만원 사이를 오간다.
**가정치로 계산했다면 이 경계 판정 자체가 무의미하다** — 실측(8-E 2 알리미)을 먼저 구한다.

- 자금(2026-09-29 강사판 반영): **단일 고정 시나리오**만 낸다(보수·중립·공격적 3시나리오는 폐기). **대출가능금액 판정을 먼저** 한다 —
  **법인 명의 + 규제지역 주택(근린주택·다가구 포함) → 0원**(은행업감독규정 별표6 제16호 — 그 답변에서 `korean-law` 로 조회한 뒤 [확정]) /
  개인 명의 + 규제지역 + 1주택 이상 보유 세대는 기존 주택 처분 조건 등 제한이 크다 `[검증필요 — 최신 대책 확인]` /
  비규제지역·비주택만 낙찰가 × 80%·연 5.5% 를 기본 가정으로 둔다(금리를 지정하면 그 값). 규제지역 여부는 그 답변에서 최신 고시로 확인한다.
  대출 0원이면 무차입 Cash-on-Cash를 내고 DSCR은 「해당 없음」. 제1 지표 = Cash-on-Cash = (연 NOI − 이자 − 첫 과세연도 보유세) ÷ 자기자본(총투입 − 대출 − 승계 보증금).
  비율(낙찰가율·LTV)이 제목·표 머리에 나오면 환산 금액을 괄호로 붙인다. DSCR이 1.0 미만이면 역레버리지 경고를 결론에 쓴다.
  **월 순현금흐름**을 함께 내고, 공실 시 역레버리지 여부를 밝힌다.
  다가구·단독주택은 세대별 분할 담보·분할 매각이 안 된다.
  **단독주택 1가구는 임대수익 모델이 아니다.** 실거주·매각이 출구다.
  **명도 공백기 이자를 총투입에 반드시 넣는다** — 명도 6~12개월 동안 임대수입은 0인데 이자는 나간다.
- 명도 지연 민감도: 「명도가 3개월 늦어질 경우」 행을 반드시 낸다. 기준 공실 기간은 STEP 10 「협의로 집이 비는 날」과 같게 둔다.
- 명도: `post-auction-eviction` 으로 D+7 ~ D+90. **점유자 수만큼 인도명령이 필요하다.**
  폐문부재·이사불명 건수를 난이도에 반영한다. 합의 이사비가 강제집행보다 싸다.
  **채무자가 절차에 무대응이면** 연락 두절로 송달이 늦어질 수 있다.

## ★ 출력 — PPTX 물건카드 (좌표를 손으로 찍지 않는다)

`pptxgenjs` 로 만든다 (`pres.layout='LAYOUT_WIDE'`, hex 에 `#` 금지).

### ★★ 표는 12행 이하로 만든다

**한 슬라이드의 표가 12행을 넘으면 아래 박스와 겹친다.** 13행 이상이면 항목을 묶거나 슬라이드를 쪼갠다.
**표 1개 + 박스 2개**가 한 장의 한계다. 세금은 처음부터 **재산세 / 종부세 / 로드맵 세 장**으로 나눈다.

### ★ 마크다운은 해석되지 않는다

pptxgenjs 는 `**굵게**` 를 파싱하지 않고 별표를 그대로 찍는다.
강조가 필요하면 `options: { bold: true }` 를 쓰거나 「 」 로 감싼다.

### 흐름 배치 엔진 — 겹침을 원천 차단한다

y좌표를 고정하면 행이 늘거나 글자가 길어질 때 **반드시 겹친다.** 아래 엔진을 쓴다.

```js
const TOP=1.36, BOTTOM=6.62, GAP=0.14;   // 러너는 y=7.08
const OVER=[];                            // 넘친 슬라이드 기록

function plain(t){ if(t==null) return '';
  if(Array.isArray(t)) return t.map(o=>plain(o&&o.text!==undefined?o.text:o)).join('');
  if(typeof t==='object') return plain(t.text); return String(t); }
function visualLen(s){ let L=0; for(const ch of s) L += /[ᄀ-ᇿ㄰-㆏가-힯]/.test(ch)?1:0.56; return L; }
function lineCount(text,colWin,fs){
  const segs=plain(text).split('\n');
  const per=Math.max(4, ((colWin-0.20)*72)/(fs*0.98));
  return segs.reduce((a,s)=>a+Math.max(1,Math.ceil(visualLen(s)/per)),0); }
function tableHeight(rows,colW,fs){ const lh=fs*1.42/72, pad=0.115;
  return rows.reduce((h,row)=>{ let mx=1;
    row.forEach((c,i)=>{ mx=Math.max(mx,lineCount(c,colW[i]||2,fs)); });
    return h+mx*lh+pad; },0); }
function boxHeight(rich,w,base){
  const fs=Math.max(...(Array.isArray(rich)?rich:[rich]).map(o=>(o&&o.options&&o.options.fontSize)||base||10.5));
  return lineCount(rich,w,fs)*(fs*1.42/72)+0.30; }
function fit(s,h,tag){ const y=s._y;
  if(y+h>BOTTOM+0.001) OVER.push(`${s._no}쪽 ${tag}: ${(y+h-BOTTOM).toFixed(2)}인치 초과`);
  s._y=y+h+GAP; return y; }
function autoFont(s,measure,fs0,min){ min=min||8;
  for(let fs=fs0; fs>=min; fs-=0.25) if(s._y+measure(fs)<=BOTTOM) return fs;
  return min; }
```

- `slide()` 는 `s._y = TOP` 으로 커서를 초기화한다.
- `tbl()` 은 `autoFont` 로 남은 공간에 맞는 폰트를 찾고 `fit()` 으로 y를 받는다.
- `box()` 는 텍스트의 `fontSize` 를 비율로 줄여가며 맞춘다(하한 7~8pt). 전폭/좌우 2단을 구분한다.
- 출처 각주는 `y=6.78` 고정. 러너는 `y=7.08`.
- **폰트 하한에 걸려도 넘치면 폰트가 아니라 내용을 줄인다.** 표를 묶거나 슬라이드를 쪼갠다.

### 생성 후 반드시

```
1. pptx 스킬 scripts/office/validate.py 로 검증
2. OVER 목록 출력 — 한 건이라도 있으면 내용을 옮기거나 슬라이드를 쪼갠다
3. PDF 로 변환해 대표 슬라이드를 이미지로 열어 눈으로 확인
   ★ 변환·렌더링은 전부 /tmp 안에서만 한다. 물건 폴더에 PDF·PNG 를 남기지 않는다
4. 발표자 노트가 전 슬라이드에 있는지 확인
```

**산출물은 PPTX 1부뿐이다.** PDF·이미지는 검증용 중간물이므로 `/tmp` 에서 만들고 그대로 버린다.
3번을 건너뛰지 마라 — `validate.py` 와 넘침 카운터는 레이아웃만 본다.
**글자 잘림·표 깨짐·마크다운 별표 노출은 눈으로만 잡힌다.**

**PowerPoint 가 파일을 열고 있으면 덮어쓰기가 막힌다.** `ppt_close_presentation` 으로 닫고 다시 쓴다.
닫을 수 없으면 **버전 파일을 새로 만들지 말고** 사용자에게 알리고 기다린다.
생성은 `/tmp` 에 하고 PPTX만 폴더로 복사한다. **덮어쓰기 전 `백업/` 에 사본을 남긴다.**

**「확인해야 할 것」이 결론이다.** 우선순위(최우선/높음/중간)를 매긴다.
해결된 항목은 지우지 말고 **「완료」로 표시**해 무엇이 닫혔는지 남긴다.

### 낙찰가 시나리오를 추가로 요청받으면

기존 슬라이드를 고치지 말고 **뒤에 별도 세트로 덧붙인다.** 첫 장에 전제(낙찰가·회차 위치·안분 비율)를
표로 깔아 앞 세트와 섞이지 않게 한다. **보유세(재산세·종부세)는 낙찰가와 무관하므로
시나리오가 달라져도 같은 값이어야 한다** — 그 사실을 슬라이드 제목에 명시한다.

**슬라이드를 중간에 끼워 넣으면 본문의 「N쪽 참조」가 전부 어긋난다.**
삽입 후 `grep -o "[0-9]\+쪽"` 으로 전수 확인하고 뒤 번호를 일괄 보정한다.
**애초에 「N쪽」 대신 「「예상 배당」 장」처럼 제목으로 참조하면 삽입에 안전하다.**

- **법정기일·금액을 모르는 선순위 조세를 0원으로 채워 「인수 0원」 결론 내기** — X `[정보부족]` + 민감도 표 (STEP 4-C)
- **압류가 임차인 기준일보다 6개월 넘게 늦다고 「안전」 판정하기** — 압류는 법정기일보다 수년 뒤일 수 있다
- **등기명의인표시경정을 채권자 변경으로 읽기** — 오기 정정이지 승계가 아니다
- **STEP 7 전에 세금·자금·민감도의 가정 낙찰가를 정하기 / 시세를 보고 정한 금액을 출처 표시 없이 여러 장에 쓰기**
- **「낙찰 후 일정표」 없이 끝내기 / 일정 날짜를 손으로 세기 / 정해진 매각기일을 D+ 로 쓰기** — STEP 10
- **낙찰가 시나리오마다 보유세가 달라지게 만들기** — 분모를 잘못 잡은 것이다
- **공시 기준연도를 빼고 공시가격만 쓰기**
- 확인 못 한 항목을 그럴듯하게 채우기
- 인수 여부를 매각물건명세서 확인 없이 단정
- 소액임차인 기준일을 계약일·전입일로 잡기
- **PDF·이미지를 물건 폴더에 남기기** — 산출물은 PPTX 1부뿐이다. 검증용 변환물은 /tmp 에서 버린다
- PPTX 좌표를 손으로 찍기 / 표를 13행 이상으로 만들기 / 마크다운 `**` 로 강조하기
- 특정 물건의 입찰 **권유**
- NPL 채권 매입가 산정

## 다른 스킬과의 관계

```
auction-doc-intake    서류를 표준 구조로 분류한다        ← 이 스킬보다 먼저
     ↓
이 스킬 (auction-property-card)   서류 → 분석 → PPTX 물건카드
     ↓
priority-payment-date-rule   임차인이 있으면 최우선변제금을 여기서 판정한다
     ↓
post-auction-eviction        낙찰된 뒤 명도
```

물건 유형이 뚜렷하면 전용 스킬을 함께 쓴다 — `residential-auction`(주거용) ·
`commercial-unit-auction`(구분상가·오피스) · `land-auction`(토지) · `small-building-auction`(꼬마빌딩).
**이 스킬이 뼈대이고, 유형별 스킬은 그 유형에서 더 봐야 할 항목을 얹는 것**이다.

**공시가격 규칙은 이 스킬 8-E 가 정본이다.**
**역세권 측정 절차는 이 스킬 STEP 5-B 가 정본이다.**
입지·상권·규제는 별도 스킬이 아니라 **STEP 5-B + `vworld-landuse` MCP** 로 본다.

> 입찰 금액을 계산해 주는 스킬은 이 배포본에 없다. STEP 7 을 따른다.
> 강사판 연계 스킬 — `auction-bid-price`(입찰가 4단계 산정표) · `post-auction-schedule`(낙찰 후 일정표) · `auction-failure-guard`(실패위험 점검표 11유형) · `npl-svg-chart`(도표 3종) · `property-tax-apportionment`(공시가격·안분)는 이 교재에는 없음 — auction-guide-kr 에 있음.
