# 물건 입지·호재 자동조사 스킬

물건 주소 하나로 **입지·규제·상권·호재·시세추세**를 자동 수집해 물건카드에 붙일 표준 섹션을 만든다.

**금액은 이 스킬이 정하지 않는다.** 입찰가·매입가는 여기서 정리한 근거를 보고 사용자가 직접 정한다.

## 이 스킬의 설계 원칙 (먼저 읽을 것)

### 원칙 1 — 호재를 정량 가산하지 않는다

"2~3년 후 지하철 개통" 같은 호재는 **이미 감정가와 최근 실거래에 부분 반영**되어 있다. 여기에 별도 프리미엄을 얹으면 이중계산이다.

- 호재는 **체크 항목**으로 기록한다. 가중치를 곱하지 않는다.
- 호재의 가격 효과는 **최근 6개월 실거래 추세**로만 읽는다.
- 유일한 예외: 개통이 확정·착공된 노선이 **실거래에 아직 반영 안 된 것이 명백**할 때. 이때도 기준 시세를 올려 잡지 말고 "회차 대기 시 경쟁 증가 위험"으로 표기한다.

### 원칙 2 — 통계 계수와 물건 정보는 계층을 분리한다

| 계층 | 담당 | 출처 |
|---|---|---|
| 통계 계층 (전국 공통) | 응찰 확률·낙찰가율 | 경매·공매 실측 통계 |
| **물건 계층 (개별)** | **실거래·상권·호재·규제** | **이 스킬** |

이 스킬의 산출물은 **사용자가 금액을 판단할 때 쓰는 근거 자료**이지, 낙찰가율 계수를 조정하는 입력이 아니다. 계수를 물건별로 흔들지 않는다.

### 원칙 3 — 입지 평가는 "몇 회차에 팔릴 물건인가"로 가늠한다

입지가 좋을수록 이른 회차에 팔린다고들 보지만, **이 스킬에는 이를 뒷받침할 회차별 통계표가 없다.** 그러므로 회차 판정은 수치가 아니라 정성 판단이며, 같은 지역·같은 용도의 최근 낙찰 사례를 직접 찾아 대조한 뒤에만 근거로 쓴다.

## 조사 절차

### STEP 0 — 주소 정규화

물건명(`onbidCltrNm`)이나 등기부에서 **지번 주소**를 추출한다. 동·호수는 떼고 지번까지만 쓴다.

```
"경기도 ○○시 ○○구 ○○동 100 ○○아파트 제504동 제5층 제504호"
  → "경기도 ○○시 ○○구 ○○동 100"
```

단지명과 전용면적은 STEP 4에서 실거래 매칭 키로 쓰므로 따로 보관한다.

주소가 마스킹(`***`)되어 있으면 이 스킬을 진행할 수 없다. 감정평가서·등기부에서 주소를 확보한 뒤 재시도한다.

### STEP 1 — 좌표·규제 (vworld-landuse)

```
mcp__vworld-landuse__get_land_use_plan(address="경기도 ○○시 ○○구 ○○동 100")
```

한 번 호출로 좌표·PNU·개별공시지가·용도지역·규제가 모두 나온다. `geocode_address`를 따로 부를 필요 없다.

| 항목 | 필드 | 활용 |
|---|---|---|
| 좌표 | `geocode.x`, `geocode.y` | STEP 3 상권조회 입력 |
| 개별공시지가 | `parcel.jiga` (원/㎡) | 감정가 타당성 교차검증 |
| 용도지역 | `zoning[]` LT_C_UQ111 `uname` | 건폐율·용적률, 활용도 |
| **규제** | `zoning[]` 기타 레이어 | **토지거래허가구역·개발제한구역 등** |

**토지거래허가구역이 나오면 결론 첫머리에 반드시 명시한다.** 낙찰 후 허가 절차가 붙는다.

`zoning`이 빈 배열이면 레이어 ID 문제이므로 `probe_layer`로 확인한다.

### STEP 2 — 역세권·개통예정 (카카오맵 + 웹검색 병행)

> `datagokr urban_rail_route`는 **폐기**되었다(오류코드 12). 호출 금지.

```
KakaoMap-SearchPlaceByKeywordOpen(keyword="<시군구> <읍면동> 지하철역")
```

응답에 `(2026년12월예정)` 같은 표기가 붙으면 개통예정역이다. 실측 예: `○○역 (2026년12월예정)`.

**카카오맵만 믿지 말 것.** 예정역 표기가 항상 나오지는 않는다(평택 고덕 조회 시 예정역 미표시 확인).

1. 카카오맵에서 예정역이 **잡히면** → [확정], 역명·예정시기 기록
2. **안 잡혀도 "없다"고 단정 금지** → `WebSearch`로 "<시군구> 지하철 연장 개통 예정", "<시군구> GTX", "<시군구> 신설역" 교차 확인 후 [검증필요]
3. 개통일은 국토부·지자체 **공식 고시**를 확인해야만 [확정]
4. 도보 거리는 `KakaoMap-GetWalkDirections`로 확인. 역명만으로 거리를 추정하지 않는다

### STEP 3 — 상권 밀도·구성 (datagokr 소상공인)

```
mcp__datagokr__sbiz_stores_in_radius(cx=<경도>, cy=<위도>, radius=500, num_of_rows=1)
  → total_count 가 반경 500m 내 점포 수
```

`num_of_rows=1`로 `total_count`만 먼저 받고, 업종 구성이 필요하면 `num_of_rows=100`으로 재조회해 `indsLclsNm`을 집계한다.

**상권 밀도 해석 기준 (2026-08-04 실측 앵커, 반경 500m)**

| 점포 수 | 등급 | 실측 기준점 |
|---:|---|---|
| 4,000+ | 최상급 광역상권 | 강남역 6,615 |
| 1,500~4,000 | 거점 상권 | 수원역 2,092 |
| 700~1,500 | 지역 중심 상권 | 양평읍 중심 736 |
| 300~700 | 근린 생활권 | ○○시 ○○동 주거지 343 |
| ~300 | 상권 미형성 | — |

- 상가·업무용: 반경 **250m**도 함께 조회한다. 근접 밀도가 실제 배후수요다
- 주거용: 500m 기준으로 생활 편의성만 본다. 밀도가 높다고 좋은 게 아니다
- 토지·임야: 생략 가능

### STEP 4 — 실거래 (★ 전량 조회 필수)

#### 규칙 4-1: 반드시 전량 조회한다 — 이걸 어기면 동일 단지 거래를 놓친다

**실측 사고 사례**: `get_apartment_trades(num_of_rows=100)`로 어느 시군구의 한 달치를 조회했을 때 총 145건 중 96건만 표본되어 **찾던 단지의 거래가 아예 보이지 않았다.** 전량 조회하니 동일 단지·동일 전용면적 거래가 실제로 존재했다. 이 차이가 기준 시세를 그대로 바꾼다.

- MCP 사용 시 `num_of_rows`를 **1000**으로 지정한다. 기본값(100) 금지
- 6개월치를 훑어야 하므로, 가능하면 **직접 HTTP 호출**로 받아 로컬에서 필터링한다(토큰 절약 + 누락 방지)

```
엔드포인트: https://apis.data.go.kr/1613000/RTMSDataSvcAptTrade/getRTMSDataSvcAptTrade
파라미터  : serviceKey, LAWD_CD(시군구 5자리), DEAL_YMD(YYYYMM), numOfRows=1000, pageNo=1
응답      : XML (JSON 아님). ElementTree로 <item> 순회
주요 필드 : aptNm, umdNm(법정동), excluUseAr(전용㎡), dealAmount(만원 단위 문자열), floor, dealDay
```

용도별 서비스 경로: 아파트 `RTMSDataSvcAptTrade` / 오피스텔 `RTMSDataSvcOffiTrade` / 연립다세대 `RTMSDataSvcRHTrade` / 단독다가구 `RTMSDataSvcSHTrade` / 상업업무용 `RTMSDataSvcNrgTrade`.
MCP로 할 경우: `get_apartment_trades` / `get_officetel_trades` / `get_villa_trades` / `get_single_house_trades` / `get_commercial_trade`.

시군구코드는 `get_region_code` 또는 `legal_dong_code_search`로 얻는다.

#### 규칙 4-2: 시세 출처 (절대)

- **국토교통부 실거래가만** 사용한다. `real-estate` MCP 우선, 실패 시 `datagokr realprice_*` fallback
- KB부동산·호갱노노·아실·부동산지인·리치고 등 제3자 추정시세는 **조회·인용·산출물 포함 전부 금지**
- 네이버부동산 호가는 사용자가 명시 요청할 때만

#### 규칙 4-3: 기준 시세 선정 우선순위

1. **동일 단지 + 동일 전용면적** (가장 신뢰) → [확정]
2. 동일 단지 + 유사 면적 → [확정], 면적 보정 명시
3. 동일 법정동 + 유사 면적(±10%) 중앙값 → [추정] 표기 필수
4. 거래 없음 → **"최근 6개월 거래 없음"을 그대로 기록.** 추정 시세를 지어내지 않는다

6개월 월별 중앙값을 나열해 방향과 변화율을 함께 제시한다. 단, 월별 중앙값은 거래 면적 구성에 따라 크게 흔들리므로 추세 해석에는 [추정]을 붙인다.

## 낙찰가율 계수는 이 스킬에 없다

이 스킬은 **조사와 정리까지만** 한다. 금액은 정하지 않는다.

기준 시세를 잡았으면 아래를 사용자에게 안내하고, 마지막 금액은 사용자가 정하게 한다.

- **저감률을 먼저 확인하라.** 법원마다 20%/30%로 갈린다.
  서울 5개 법원(중앙·남부·동부·서부·북부)과 수원지법 안양지원은 20% 저감이라
  1회 유찰 최저가가 **80%** 다.
- **인근 낙찰 사례를 직접 대조하라.** 법원경매정보와 온비드에서
  같은 지역·같은 용도·같은 유찰 회차의 최근 낙찰가를 찾는다.

추정 낙찰가를 굳이 제시할 때는 `[추정]` 라벨과 근거(표본 수·기간)를 반드시 함께 쓴다.

```markdown
### 4. 실거래  [확정] 국토교통부 실거래가

- **동일 단지·동일 면적 거래: <있음/없음>** ← 전량 조회로 확인

### 5. 회차 관점 판정
- 본건이 몇 회차인지 적고, 같은 지역·같은 용도의 최근 낙찰 사례를 직접 찾아 대조하도록 안내한다
- 경쟁강도 가늠: <높음/보통/낮음> — 수치 보정이 아니라 정성 판단이다

### 6. 확인 필요 사항
```

## 금액·라벨 표기 규칙

- 원화 금액은 **원 단위 풀 콤마**로만: `366,777,700원`. 만·억 축약 금지(그래프 축 라벨만 예외)
- 모든 사실 문장 앞에 **[확정] / [검증필요] / [추정]** 라벨
- [확정]은 이 세션에서 직접 호출한 결과만. 출처(MCP명·레이어 ID·엔드포인트)를 함께 쓴다
- 웹검색으로만 확인한 개통 계획은 [검증필요]. 공식 고시번호 확인 시에만 [확정]

## 실패 시 처리

| 증상 | 처리 |
|---|---|
| geocode 실패 | 도로명↔지번 바꿔 재시도. 그래도 실패 시 인접 지번으로 좌표만 확보하고 [추정] |
| `zoning` 빈 배열 | `probe_layer`로 레이어 ID 확인 |
| `urban_rail_route` | **호출 금지 — 폐기된 API.** 카카오맵 사용 |
| 실거래 응답이 XML | 정상이다. ElementTree로 `<item>` 순회 |
| 동일 단지 거래 없음 | **전량 조회(numOfRows=1000)로 먼저 재확인.** 그래도 없으면 법정동 프록시 [추정] |
| 주소 마스킹 | 진행 불가. 감정평가서·등기부에서 주소 확보 후 재시도 |

## 연계

- 선행: 감정평가서·등기부 등 서류에서 지번 주소 확보
- 후속: 조사 결과를 사용자에게 그대로 제시한다. 입찰가·매입가 결정은 사용자가 직접 한다
- 용도별 심화: `residential-auction` / `commercial-unit-auction` / `land-auction` / `small-building-auction`
