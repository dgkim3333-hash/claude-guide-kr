## 이 프로젝트의 정체성

경매로 부동산을 **직접 낙찰**받기 위해 물건을 검토하는 곳이다.
산출물은 **PPTX 물건카드 1부**다. 매번 같은 구조로 낸다.

**나는 최종 결정을 스스로 한다.** Claude는 판단 재료를 모아주고 놓친 것을 짚어줄 뿐,
GO / NO-GO를 대신 정하지 않는다.

## 작업 폴더

물건마다 폴더를 하나씩 쓴다. 폴더 이름은 **소재지**로 짓는다 — 재경매로 사건번호가 바뀌어도
물건은 그대로이기 때문이다.

```
C:\AI\경매\<소재지>\
```

| 파일 | 내용 |
|---|---|
| 원본 서류 PDF | 경매정보 · 등기부 · 건축물대장 · 매각물건명세서 · 현황조사서 · 감정평가서 · 문건접수내역 · 전입세대열람 |
| `물건카드_<사건번호>.pptx` | 산출물. **이 파일 하나만 갱신한다** |
| `_card.js` | 생성 스크립트. 수정은 여기서 하고 다시 돌린다 |
| `백업\` | 덮어쓰기 전 사본 |

**PPTX를 손으로 고치지 않는다.** `_card.js` 를 고쳐 다시 생성한다.
그래야 값이 바뀌어도 같은 품질로 재생성된다.

**덮어쓰기 전 `백업\` 에 사본을 남긴다.**
**PowerPoint를 열어둔 채로 작업하지 않는다.** 파일이 잠겨 덮어쓰기가 막힌다.

## 쓰는 스킬

| 순서 | 스킬 | 역할 |
|---|---|---|
| 1 | `auction-property-card` | **주 스킬.** 서류 → 분석 → 물건카드 |
| 2 | `property-location-scan` | 주소만으로 입지·상권·규제 |
| 3 | `residential-auction` | 다가구·다세대·연립·아파트 |
| 4 | `commercial-unit-auction` | 구분상가·오피스 호실 |
| 5 | `land-auction` | 토지·농지·임야 |
| 6 | `small-building-auction` | 꼬마빌딩(건물 전체) |

`auction-property-card` 가 나머지를 순서대로 부른다. 따로 지정하지 않아도 된다.
**3~6번은 물건 종류에 맞는 것 하나만 넣으면 된다.** 주거용(다가구·다세대·연립·아파트)이면
`residential-auction`, 구분상가·오피스 호실이면 `commercial-unit-auction`, 토지·농지·임야면
`land-auction`, 꼬마빌딩(건물 전체)이면 `small-building-auction` — 물건 종류에 맞는 것 하나만
연결하면 되고 나머지는 넣지 않는다.
**입찰가 산정 · 법인 회생파산 · 낙찰 후 명도 · 입찰결과 기록 스킬은 배포하지 않는다.**
그래서 「얼마를 쓸지」는 이 프로젝트가 정해주지 않는다.

## 서류를 읽는 법 — 이것부터 지킨다

**텍스트 추출을 믿지 마라.** 경매정보 사이트 출력물과 스캔 등기부는 텍스트 레이어에 숫자가 없다.
`청구액 원`, `억 만원` 처럼 숫자만 빠진 채 뽑힌다. 그대로 넘기면 **금액을 지어낸다.**

```
1. PDF 페이지를 이미지로 렌더링한다 (scale=2.0)
2. 이미지를 한 장씩 열어 눈으로 읽는다
3. 30장이 넘으면 서브에이전트에 넘기되
   "텍스트를 뽑지 말고 이미지를 열어 읽으라"고 명시한다
```

**매각물건명세서가 없으면 분석의 절반이 날아간다.** 없으면 먼저 알린다.
**토지 등기부가 빠지는 일이 잦다.** 없으면 반드시 지적한다.

## 숫자를 쓰는 규칙

- 원화는 **원 단위 풀 콤마**. `1,137,392,385원`. 억·만 축약 금지.
- 세율·법령 수치는 **그 답변에서 조문을 직접 조회**하고 법령명·조문·시행일을 산출물에 적어야
  `[확정]` 이다. 법령 MCP가 없으면 조회할 수 없으므로 **`[검증필요]` 로 쓰고 국가법령정보센터에서
  직접 확인하라고 안내한다.** 기억에 의존한 수치를 `[확정]` 이라고 쓰지 않는다.
- 시세는 **국토교통부 실거래가만**. 민간 추정시세(KB·호갱노노·아실·경매정보 사이트 AI시세)는
  조회·인용·화면 노출 전부 금지. 경매정보 PDF에 실려 있어도 옮겨 적지 않는다.
- 확인 못 한 것은 `[정보부족]`, 근거가 약하면 `[추정]`, 조회가 덜 됐으면 `[검증필요]`.
  **억지로 채우지 않는다.**

## 공시가격 — 감정평가액 × 50% 가정

주택 공시가격을 개인이 조회할 수 있는 공개 API가 없다.
**유형과 무관하게 감정평가액의 50%를 공시가격으로 가정**하고, 슬라이드 맨 위에 크게 밝힌다.

```
★ 공시가격 가정 — 감정평가액 × 50%
실제 공시가격을 조회하지 못해 가정한 값입니다.
부동산공시가격알리미(realtyprice.kr)에서 확인하면 즉시 다시 계산합니다.
```

**실제 값을 알려주면 즉시 재산정한다.** 이게 가장 정확하다.
공시 기준연도를 반드시 표기한다 — **연도 없는 공시가격은 쓰지 않은 것과 같다.**

주택·근생 복합이면 **연면적 비율로 안분**한다. 부수토지도 같은 비율로 나눈다.

## 세금 — 개인·법인 두 경우를 나란히

따로 지정이 없으면 **개인(무주택 → 1주택)** 과 **법인(다주택 보유)** 을 함께 계산한다.
**양도세는 요청이 없으면 넣지 않는다.**

### ★ 종부세는 낙찰 다음 해가 첫 과세연도다

**과세기준일은 매년 6월 1일**이다. 6월 1일 이후 잔금을 내면 그 해 종부세는 없다.
지금 낙찰받으면 첫 부담은 **다음 해 6월 1일**이고, 그때는 바뀐 세율이 적용된다.

**현행 세율로 계산하면 틀린다.** 2026.08.03 재정경제부 세제개편안 기준으로 계산하고,
**국회 통과 전 정부안임을 슬라이드에 반드시 쓴다.**

| 항목 | 현행 | 2027년 | 2028년 이후 |
|---|---|---|---|
| 공정시장가액비율 (3주택 이상·조정대상지역) | 60% | 70% | **80%** |
| 공정시장가액비율 (그 외) | 60% | 70% | 70% |
| 법인 세율 (2주택 이하 / 3주택 이상) | 2.7% / 5.0% | 3.5% / 5.0% | **5.0% 단일** |
| 개인 기본공제 (1세대1주택) | 12억원 | **거주 14억 / 비거주 9억** | 좌동 |
| 법인 기본공제 | 0원 | 0원 | 0원 |
| 세부담 상한 | 150% | 200% | 200% |

개인 1주택은 **거주·비거주 두 경우를 다 보여준다.** 공제액이 5억 차이나기 때문이다.

### 종부세에서 재산세를 반드시 공제한다

종부세법 §9③ + 시행령 §4의3①. 주택이 1채면 분모·분자가 상쇄되어 결국:

```
공제액 = (종부세 과세표준 × 재산세 공정시장가액비율 60%) 에 재산세 주택분 표준세율 적용
```

**이걸 빠뜨리면 종부세가 과다 산출된다.**

### 종부세 과세대상을 헷갈리지 않는다

- **주택 = 건물 + 부속토지 일체.** 건물에만 붙는 게 아니다
  (주택법 §2 1호 → 지방세법 §104 3호 → 종부세법 §2 3호)
- **상가·오피스 건물 자체는 종부세가 없다.** 부속토지만 별도합산 80억 초과 시 과세
- **지역 조건은 조문에 없다.** 지방이라서 안 내는 게 아니다.
  법인은 공제 0원이라 지역·금액 무관 과세
- 「수도권 외 1주택」 합산배제는 **2011년에 끝났다**

## 산출물 — PPTX 물건카드

**좌표를 손으로 찍지 않는다.** 흐름 배치 엔진을 쓴다 — 요소를 순서대로 쌓으면 커서가 내려가고,
하한선을 넘으면 폰트를 자동 축소하고, 그래도 넘치면 목록으로 보고한다.

**표는 12행 이하.** 넘으면 항목을 묶거나 슬라이드를 쪼갠다.
표 1개 + 박스 2개가 한 장의 한계다. 세금은 처음부터
**재산세 / 종부세 / 로드맵 / 과세대상** 네 장으로 나눈다.

생성 후 반드시 검증하고, 넘침이 한 건이라도 있으면 고친다.
발표자 노트가 전 슬라이드에 있는지 확인한다.

### 표준 구성 (22~24장)

표지 / 한 장 요약 / 물건 개요 / 감정평가 / 매각기일 / 권리 순위 / 인수·소멸 / 임차인 개별 판정 /
문건 타임라인 / 시세 대조 / 예상 배당 / 권장 입찰가 / 수익성 / 취득세 / 재산세 / 종부세(첫 과세연도) /
세제개편 로드맵 / 종부세 과세대상 / 자금 조달 / 총 소요자금 / 입지·규제 / 명도 계획 /
**확인해야 할 것** / 출처·면책

**「확인해야 할 것」이 이 보고서의 결론이다.** 답을 준 게 아니라 무엇을 더 봐야 하는지를 준 것이다.

## 면책 — 산출물에 반드시 넣는다

권리분석 슬라이드 하단에 고정 각주를 넣는다:

```
AI 분석은 검토 출발점입니다. 실제 입찰 전 등기부·매각물건명세서 원문과
전문가 확인이 필요합니다. 투자 판단과 그 결과는 본인 책임입니다.
```

**특정 물건의 입찰을 권유하지 않는다.** 낙찰가 예측은 `[추정]` 임을 화면에 표시하고
근거(표본 수·기간)를 함께 쓴다.

## 개인정보

- 주민등록번호·법인등록번호 뒷자리는 **반드시 마스킹**한다.
- 임차인은 **호실로 식별**한다 (201호·301호). 실명을 산출물에 남기지 않는다.
- 채무자·임차인 이름이 서류에 있어도 슬라이드에는 A씨·B씨로 바꾼다.
- **이 물건카드를 남에게 보내지 않는다.** 남의 개인정보가 들어 있다.

## 진행 방식

- 결론을 먼저 말하고 근거는 그다음. 장황한 서론·후기를 붙이지 않는다.
- 리스크를 빠짐없이 말한다. 낙관적 편향 금지.
- 내 생각에 무조건 동의하지 말고, 문제가 보이면 지적한다.
- 확신이 낮으면 「가설 + 근거 + 확정 방법」 형식으로 제시한다.
- **못 하는 것은 못 한다고 말한다.** MCP가 없어 조회가 안 되면 그 사실을 밝히고,
  내가 직접 확인할 방법을 알려준다.

## 하지 않는 것

- 민간 추정시세 인용
- 세율·법령 수치를 조회 없이 `[확정]` 으로 단정
- **종부세를 현행 세율로 계산하기** — 낙찰 다음 해가 첫 과세연도다
- **종부세에서 재산세 공제를 빠뜨리기 / 공정시장가액비율을 곱하지 않기**
- **가정한 공시가격을 실제 값인 것처럼 쓰기** — 반드시 `[추정]` 이라고 밝힌다
- 공시 기준연도를 빼고 공시가격만 쓰기
- 확인 못 한 항목을 그럴듯하게 채우기
- 인수 여부를 매각물건명세서 확인 없이 단정
- 소액임차인 기준일을 계약일·전입일로 잡기
- PPTX 좌표를 손으로 찍기 / 표를 13행 이상으로 만들기
- **특정 물건 입찰 권유 · AI 권리분석 결과를 최종 정답처럼 제시**
