## 1. 이 시스템이 하는 일

### 발굴 논리

텐베거는 대부분 이 경로로 만들어집니다.

> **애널리스트 커버리지 공백 → 실적 변곡 → 첫 리포트 발간 → 재평가**

따라서 찾아야 할 것은 "실적이 좋은 종목"이 아니라
**"실적은 이미 꺾여 올라가는데 아직 아무도 보고 있지 않은 종목"**입니다.

주가 10배 = `이익 배수 × 멀티플 배수`.
한국 소형주 호황기 PER 상단이 15~25배이므로 멀티플로 얻을 수 있는 것은 현실적으로 2~3배입니다.
나머지 **3~5배는 이익 자체가 늘어야** 나옵니다. 그래서 이익의 실체를 집요하게 검증합니다.

### 4축 교차검증

| 축 | 무엇을 보나 | 데이터 출처 |
|---|---|---|
| ① 분기 궤적 | 5개 분기 영업이익이 연속 개선되는가 | DART 재무제표 |
| ② 이익의 질 | 영업이익이 실제 현금으로 들어오는가 (OCF ÷ 영업이익) | DART 현금흐름표 |
| ③ 수급 전환 | 외국인·기관이 30영업일간 사고 있는가 | 한국투자증권 KIS |
| ④ 밸류에이션 | 시가총액이 작고 PER이 낮아 10배 여력이 있는가 | KIS 시세 |

**네 축을 모두 통과해야 편입**합니다. 세 축만 통과하면 "경계종목"으로 대기시키고, 편입 조건과 확인 시점을 명시해 둡니다.

### 산출물 2개

| 산출물 | 형태 | 역할 |
|---|---|---|
| **아티팩트 `tenbagger-watch`** | Claude 안에서 열리는 라이브 관제판 | 워치리스트 상태 저장소 겸 뷰어. 열 때마다 시세·수급·뉴스를 다시 불러옴 |
| **월간 리포트** | 마크다운 파일 | 편입·제외 종목과 그 사유를 수치와 함께 기록 |

### 무엇을 하지 않는가

- **투자 추천을 하지 않습니다.** 조사 결과를 제시하고 판단은 본인이 합니다.
- **매수 시점·목표주가를 제시하지 않습니다.**
- 전환사채 오버행, 감사의견, 특수관계자 거래 등은 이 스크리닝이 자동으로 걸러내지 못합니다. 최종 편입 종목에 한해 보완 조사합니다.

### 알아둘 제약

- **예약작업은 Claude 데스크탑이 켜져 있을 때만 실행됩니다.** 매월 1일 11시에 앱이 꺼져 있으면 다음에 앱을 켤 때 실행됩니다.

- DART API는 **일일 호출 한도**가 있습니다(계정당 20,000건). 전수 스크리닝 1회에 약 2,000~4,000건을 씁니다. 하루에 여러 번 돌리지 마세요.

## 3. 1단계 — API 키 2종 발급

### 3-1. DART OpenAPI (필수, 무료)

1. https://opendart.fss.or.kr 접속
2. 상단 **인증키 신청/관리 → 인증키 신청**
3. 이메일·이름 입력 후 신청 → 메일로 40자리 인증키 수신
4. 발급 즉시 사용 가능

> **용도** 재무제표(매출·영업이익·자본총계), 현금흐름표, 공시 목록, 기업 개황, 최대주주 현황

### 3-2. 한국투자증권 KIS Developers (필수)

1. **한국투자증권 계좌가 필요합니다.** 없으면 앱으로 비대면 개설 (1~2일)
2. https://apiportal.koreainvestment.com 접속 → 로그인
3. **KIS Developers → 신청/조회 → API 신청**
4. 실전투자 또는 모의투자 선택
   - **실전투자 권장** — 모의투자는 투자자별 매매동향(수급) API가 제한될 수 있습니다
5. `APP Key`와 `APP Secret` 발급

> **용도** 실시간 시세, 시가총액, PER·PBR, 52주 고저, **외국인·기관 30영업일 순매수**, 애널리스트 컨센서스

### 3-3. 네이버 뉴스는 키가 필요 없습니다

뉴스 검색은 **PlayMCP 커넥터**로 씁니다. 개인 키를 따로 받지 않습니다.
playmcp.kakao.com 에서 도구함에 **「네이버 검색 mcp」** 를 담고, Claude 데스크탑에서 PlayMCP 커넥터를 켜면 됩니다.

> 네이버 개발자센터에서 검색 API 키를 새로 받기 어렵다는 제보가 있습니다.
> PlayMCP 로 가면 그 문제를 우회할 수 있고, 준비물도 하나 줄어듭니다.

> **용도** 종목 뉴스 검색. 공시 목록은 제목만 주기 때문에 계약 금액·상대방을 뉴스로 보완 확인합니다.

## 4. 2단계 — MCP 서버 연결

이 시스템은 MCP 3종을 씁니다.

| MCP | 제공 도구 | 무엇에 쓰나 |
|---|---|---|
| **한국주식 통합 MCP** | `koreaStock-*`, `opendart-*` | 재무제표·시세·공시·기업정보 |
| **KIS MCP** | `call-kis-api` | 외국인·기관 수급, 컨센서스 |
| **네이버 검색 MCP** (PlayMCP) | `NaverSearch-search_news` | 종목 뉴스. 개인 키 불필요 |

### 4-1. 커넥터 디렉터리에서 찾기 (가장 쉬움)

Claude 데스크탑에서 새 대화를 열고 이렇게 말합니다.

```
한국 주식 재무제표·시세·공시를 조회할 수 있는 MCP 커넥터를 찾아줘.
한국투자증권 KIS API도 같이.
```

Claude가 커넥터 레지스트리를 검색해 설치 가능한 목록을 제시합니다. 여기서 설치하는 것이 가장 안전합니다.

### 4-2. 설정 파일을 직접 편집하는 경우

> ⚠ **Microsoft Store 버전 Claude 데스크탑을 쓴다면 경로가 다릅니다.**
>
> | 설치 유형 | claude_desktop_config.json 경로 |
> |---|---|
> | **Microsoft Store 버전** | `C:\Users\<사용자명>\AppData\Local\Packages\Claude_pzs8sxrjxfjjc\LocalCache\Roaming\Claude\claude_desktop_config.json` |
> | 일반 설치 버전 (Windows) | `C:\Users\<사용자명>\AppData\Roaming\Claude\claude_desktop_config.json` |
> | macOS | `~/Library/Application Support/Claude/claude_desktop_config.json` |
>
> **Store 버전인데 `%APPDATA%\Claude\`에 넣으면 아무 일도 일어나지 않습니다.** 어느 쪽인지 모르겠으면 Claude에게 "내 MCP 설정 파일 경로 확인해줘"라고 물어보세요.

설정 파일에 API 키를 환경변수로 넣습니다. 구조는 아래와 같습니다 — **실제 서버 이름·명령어는 설치하는 MCP 패키지에 따라 다르므로, 패키지 문서를 따르세요.**

```json
{
  "mcpServers": {
    "<서버이름>": {
      "command": "<실행 명령>",
      "args": ["<패키지명>"],
      "env": {
        "DART_API_KEY": "여기에_DART_인증키_40자리",
        "KIS_APP_KEY": "여기에_KIS_APP_KEY",
        "KIS_APP_SECRET": "여기에_KIS_APP_SECRET"
      }
    }
  }
}
```

편집 후 **Claude 데스크탑을 완전히 종료했다가 다시 켭니다.** (창만 닫으면 안 되고 트레이 아이콘에서 종료)

### 4-3. 연결 확인

새 대화에서 이렇게 확인합니다.

삼성전자(005930) 현재가랑 2025년 3분기 재무제표 조회해봐.
그리고 외국인 30일 수급도.
```

세 가지가 다 나오면 성공입니다. 하나라도 안 되면 [10. 자주 나는 문제](#10-자주-나는-문제)를 보세요.

## 5. 3단계 — 내 MCP 접두어 확인 ★가장 중요

**이 단계를 건너뛰면 예약작업이 100% 실패합니다.**

MCP 도구 이름에는 서버 고유 ID가 접두어로 붙는데, **이 ID는 설치할 때마다 달라집니다.**

예를 들어 원본 시스템에서는 이랬습니다.

```
mcp__b68f9e48-afcd-44fc-b9e2-15b50d00b660__koreaStock-stock_get_quote
   └─────────── 이 부분이 사람마다 다릅니다 ───────────┘
```

친구분 환경에서는 `mcp__a1b2c3d4-...__koreaStock-stock_get_quote` 처럼 **다른 ID**가 됩니다.

### 확인 방법

새 대화에서 이렇게 물어봅니다.

```
지금 연결된 MCP 도구 중에서 koreaStock, opendart, kis, NaverSearch 관련 도구의
정확한 전체 이름(mcp__로 시작하는 풀 네임)을 그대로 알려줘.
```

Claude가 알려주는 이름을 **그대로 메모**하세요. 아래 5개가 필요합니다.

| 역할 | 원본 시스템의 이름 | 내 환경의 이름 (여기에 적으세요) |
|---|---|---|
| 시세 조회 | `{S}koreaStock-stock_get_quote` | |
| 주가 이력 | `{S}koreaStock-stock_get_price_history` | |
| 종목 뉴스 | `{S}koreaStock-market_get_news` | |
| KIS 수급 | `mcp__kis__call-kis-api` | |
| 네이버 뉴스 | `{S}NaverSearch-search_news` | |

**부록 A의 프롬프트에는 `{S}` 라는 자리표시자를 써 두었습니다.**
예약작업을 등록하기 전에 **`{S}`를 전부 본인 접두어로 바꿔치기** 하세요. (텍스트 편집기의 "모두 바꾸기" 사용)

## 필수 구조 — 이 마커를 반드시 넣어줘

<script> 안에 아래 두 블록을 마커와 함께 정확히 이 문자열로 넣어줘.
나중에 자동화가 이 마커를 이름으로 찾아서 블록을 통째로 교체해. 마커 이름(WATCHLIST_START 등)은 정확해야 하지만, 양옆 등호 개수나 이름 뒤에 붙는 설명 문구는 자동화가 신경 쓰지 않으니 달라져도 돼.

/* ==== WATCHLIST_START ==== */
const WATCH = [];
const BORDER = [];
/* ==== WATCHLIST_END ==== */

/* ==== CHANGELOG_START ==== */
const CHANGELOG = [];
/* ==== CHANGELOG_END ==== */

## 화면 구성 — 탭 6개

1. 종목 현황 — WATCH를 표로. 컬럼: 종목명 / 티커 / 현재가 / 등락률 / 시가총액(원) /
   외국인 5일(주) / 외국인 30일(주) / 기관 30일(주) / 52주 고점 대비 / PER / 궤적 / 현금흐름 / 테마
   티커를 누르면 네이버 금융(https://finance.naver.com/item/main.naver?code=티커)으로 이동
   그 아래에 종목별 20영업일 주가 미니차트 그리드
2. 종목별 상세 — WATCH 각 항목을 카드로. biz / products / customers / competitors /
   industry / shareholder / issues / point / risk / trigger / src 전부 표시
3. 경계종목 · 편입 조건 — BORDER 각 항목을 카드로. why / cond / when 표시
4. 뉴스 — 테마 뉴스(네이버)와 종목 뉴스(KIS)
5. 변경 이력 — CHANGELOG를 시간순으로. added는 초록 테두리, removed는 빨강 테두리
6. 편입 근거 — 편입 시점에 고정된 4축 수치 표 (새로고침해도 안 바뀜)

## 10. 자주 나는 문제

### MCP가 연결되지 않습니다

| 증상 | 원인과 처방 |
|---|---|
| 재시작해도 도구가 안 보임 | **Store 버전인데 `%APPDATA%\Claude\`에 설정을 넣었을 가능성.** 4-2의 Store 경로로 다시 넣으세요 |
| `Server disconnected` | 설정 파일 JSON 문법 오류. 쉼표·중괄호 확인. 온라인 JSON 검증기에 붙여넣어 보세요 |
| `ModuleNotFoundError` | 패키지 미설치. 해당 MCP 문서의 설치 명령 재실행 |
| 창만 닫았다 열었는데 안 됨 | **완전 종료가 필요합니다.** 트레이 아이콘 우클릭 → 종료 |

Claude에게 "MCP 연결 안 됨, 진단해줘"라고 하면 로그를 읽고 원인을 짚어줍니다.

### DART 조회가 전부 `NO_DATA`

- **정상일 수 있습니다.** 해당 분기 보고서가 아직 공시되지 않은 것입니다
- 공시 시점: 1분기 5월 중순 / 반기 8월 중순 / 3분기 11월 중순 / 사업보고서 3월 말
- **판별법** — 삼성전자(005930)로 같은 파라미터를 조회해 보세요. 삼성전자도 `NO_DATA`면 미공시, 삼성전자만 되면 그 종목의 문제입니다

### KIS 수급 조회가 안 됩니다

- 모의투자 계정은 투자자별 매매동향 API가 제한될 수 있습니다. **실전투자 계정 키**로 바꿔보세요
- KIS는 토큰 유효기간이 있어 장시간 미사용 후 첫 호출이 실패할 수 있습니다. 한 번 더 호출하면 됩니다

### `rate limit` 오류가 쏟아집니다

- DART API 일일 한도(20,000건)를 넘었을 가능성. 다음 날 재시도
- 프롬프트에 재시도 지시가 들어 있으므로 일시적 rate limit은 자동 복구됩니다
- 하루에 전수 스크리닝을 두 번 이상 돌리지 마세요

### 아티팩트를 수정할 수 없다고 나옵니다

- **정상 동작입니다.** `list_artifacts`가 준 경로의 파일은 읽기 전용입니다
- 산출물 폴더에 새 HTML을 만들어 `update_artifact`에 넘기는 것이 정해진 절차입니다
- 프롬프트에 이 절차가 들어 있으니 Claude가 알아서 처리합니다

### 아티팩트 원본을 읽지 못합니다

- 경로에 한글이 깨져 보여도(`臾몄꽌` 등) **`list_artifacts`가 준 문자열을 그대로** 쓰면 읽힙니다. 예쁘게 고치려 하면 실패합니다
- 폴더 접근 권한을 요청하는 방식은 막힐 수 있습니다. **파일 단위로 직접 Read** 하세요

### 금액이 "12.3억원" 처럼 축약돼 나옵니다

- 프롬프트의 표기 규칙이 무시된 것입니다. "원 단위 풀 콤마로 다시 써줘"라고 지시하세요
- 아티팩트라면 `mcapIn` 필드만 예외(억원 단위 숫자)이고 나머지는 전부 원 단위여야 합니다

### 리포트에 근거 없는 수치가 보입니다

- **가장 위험한 실패입니다.** "이 수치의 출처가 되는 MCP 호출 결과를 보여줘"라고 되물으세요
- 프롬프트에 "데이터를 지어내지 않는다 / 조회 실패는 데이터 없음으로 명시" 원칙이 들어 있지만, 확인하는 습관을 들이는 편이 안전합니다

한국 상장주식 중 향후 2~3년 내 10배가 될 가능성이 있는 종목을 4축 교차검증으로 발굴하고, 워치리스트를 갱신한다.

**되묻지 마라. 이 문서가 실행 절차 그 자체다.** 예약된 작업·노트·메모를 검색하지 말고 아래 0단계부터 바로 시작한다.

**이미 오른 종목을 채점하는 것이 아니라, 아직 오르지 않은 종목을 찾는 것**이 목적이다.

### 0단계 — 현재 상태 파일 읽기 (반드시 먼저)

현재 워치리스트의 원본은 **아티팩트 `tenbagger-watch`** 다.

```
mcp__cowork__list_artifacts          → id="tenbagger-watch" 의 path 확인
Read <그 path>                        → 원문 그대로 사용. 경로를 추측하지 마라
```

- 경로에 한글이 깨져 보여도 **list_artifacts가 준 문자열을 그대로** Read에 넘긴다.
- 파일이 커서 Read가 페이지로 잘리면 `offset`/`limit`으로 끝까지 읽는다.
- 추출할 것 — `const WATCH = [...]`, `const BORDER = [...]`, `const CHANGELOG = [...]` 세 블록. 이것이 보유 워치리스트·경계종목·변경이력의 **단일 진실 원천**이다.
- 각 WATCH 항목의 `trigger`, 각 BORDER 항목의 `cond`/`when`이 이번 회차에 점검할 개별 조건이다.
- WATCH가 빈 배열이면 최초 실행이다. 중복 점검을 건너뛰고 곧바로 전체 7단계를 실행한다.
- Read가 끝내 실패하면 그 사실을 리포트에 명시하고, 신규 발굴만 수행한 뒤 diff는 "직전 상태 확인 불가"로 처리한다.

### 실행 전 중복 점검

전수 스크리닝은 서브에이전트 12~14개에 25분이 걸린다. 새 데이터가 없으면 같은 결과가 나온다.

CHANGELOG 맨 앞 항목의 `date`와 오늘 날짜를 비교한다.

| 상황 | 조치 |
|---|---|
| CHANGELOG가 비어 있음 (최초 실행) | **전체 7단계 실행** |
| 마지막 실행 이후 분기보고서 공시가 있었다 | **전체 7단계 실행** |
| 5영업일 이상 경과, 분기 공시 없음 | **5단계만 실행** (트리거·경계종목 점검) |
| 5영업일 미만 또는 같은 날 | **실행하지 않는다.** 아래 형식으로 보고하고 종료 |

**분기보고서 공시 여부는 추측하지 말고 직접 조회한다.** 달력만 보고 판단하지 않는다.
보유 종목 3개(없으면 삼성전자 005930 등 임의 3종목)로 아래를 호출해 교차 확인한다.

```
{S}koreaStock-dart_get_financial_statement
  { stockCode:"<티커>", year:"<당해>", reportCode:"<직전 분기 코드>" }
```

- **3종목 모두 `NO_DATA`** → 미공시. 실적 기반 판정은 **불가**로 리포트에 명시하고 수급·시총·공시 기반 트리거만 점검한다.
- **하나라도 데이터가 나옴** → 공시 시작됨. 전체 7단계 실행.

| 보고서 | reportCode | 통상 공시 시점 |
|---|---|---|
| 1분기 | `11013` | 5월 중순 |
| 반기(2분기) | `11012` | 8월 중순 |
| 3분기 | `11014` | 11월 중순 |
| 사업보고서(연간) | `11011` | 3월 말 |

**실행하지 않을 때의 보고 형식** (선택지를 제시하지 말 것):

> **재실행 불필요** — 마지막 실행 `<CHANGELOG 최신 date>`, 오늘 `YYYY-MM-DD`.
> 그 사이 새 분기보고서 공시가 없고 거래일이 N일 경과했습니다.
> 지금 전수 스크리닝을 돌리면 직전 회차와 동일한 결과가 나옵니다.
> **다음 실행 권장 시점** — 전체 재실행: (다음 분기보고서 공시일) / 트리거 점검: (5영업일 경과 시점)

### 절대 원칙

1. **데이터를 지어내지 않는다.** 모든 수치는 MCP 실호출 결과여야 한다. 조회 실패는 "데이터 없음", 검색 실패는 "확인 불가"로 명시한다.
2. **금액은 원 단위 풀 콤마.** `1,234,567,890원`. 억·만·조 단위 축약 금지. 그래프 축 라벨만 예외. 저장 전 정규식으로 자가 검사한다.
3. **제3자 추정시세 금지.** 시세·수급은 KIS, 재무는 DART 원본만 사용한다.
4. **한 분기 숫자로 방향을 판단하지 않는다.** 분기 궤적과 현금흐름을 반드시 함께 본다.
5. **수급 단독으로 편입하지 않는다.**
6. **통과선에 예외를 만들지 않는다.** 미달하면 사정이 좋아 보여도 보류한다.
7. **투자 추천을 하지 않는다.** 조사 결과를 제시하고 판단은 사용자에게 맡긴다. 리스크를 축소하지 않는다.
8. **공시는 제목이 아니라 본문을 연다.** 제목만으로 판정하면 오독한다.
9. **52주 고저·주가 변동률은 액면병합·소각 이력을 먼저 확인하고 쓴다.**
10. **트리거가 한 번 충족되면 재정의한다.** 이미 벌어진 일을 계속 감시 항목으로 두지 않는다.

**① 수급이 최상위여도 현금흐름이 마이너스면 편입하지 않는다**
에이치엠넥스(036170) — 외국인이 30영업일 중 25일 순매수하며 1,596,710주 매집, 52주 고점 대비 25%로 가장 눌려 있었으나 영업이익 867,558,616원에 영업활동현금흐름 -137,523,121원. 매출채권 및 기타유동채권 +11,127,000,240원. **수급은 확인 신호일 뿐 이익의 질을 대체하지 못한다.**

**② 매출 급증이 곧 이익의 질은 아니다**
미래반도체(254490) — 영업이익 32,176,733,207원인데 영업활동현금흐름 -95,759,272,549원. 매출채권 +45,311,086,820원·재고자산 +89,459,810,790원을 차입금 108,000,000,000원으로 메웠다. 시가총액 197,900,000,000원의 절반이 넘는 차입.

영우디에스피(143540) — 궤적은 가장 깨끗한데 외국인 777,177주 순매도. DART 공시 27건 전수 확인 결과 유상증자·전환사채·감자·실적 경고가 한 건도 없었고 오히려 대주주 지분 증가, 임원 자사주 183,000주 매입만 확인됐다. **추정으로 판정하지 말고 공시를 직접 확인한다.**

### 스크리닝 기준 (4축)

#### 1단계 — 유니버스

| 항목 | 기준 |
|---|---|
| 시장 | KOSPI + KOSDAQ (KOSDAQ GLOBAL 포함) |
| 시가총액 | 30,000,000,000원 이상 ~ 1,000,000,000,000원 이하 |
| 제외 | KONEX, 우선주(코드에 K/L 포함), 리츠, 스팩 |

```
{S}koreaStock-get_stock_master { market:"ALL" }
```
- 반환 약 2,874종목. 필드 `stock_code, name, market, market_cap`
- **market_cap 단위는 억원.** 원 환산은 ×100,000,000
- 응답 300KB로 컨텍스트 초과 → 저장된 파일을 python/jq로 파싱한다

#### 2단계 — 실적 변곡 (전수 스크리닝)

**직전 분기 vs 전년 동기.** 아래를 **모두** 만족해야 통과.
1. 직전 분기 영업이익 > 0
2. 직전 분기 자본총계 > 0 (자본잠식 제외)
3. 매출 증가율 ≥ **15%**
4. 전년 동기 영업이익 ≤ 0 (흑자전환) **또는** 영업이익 증가율 ≥ **40%**

1,000종목이 넘으므로 **반드시 서브에이전트 10~14개로 분할 병렬 처리**한다.
종목 목록은 파일로 써서 경로만 전달하고 에이전트가 bash로 읽게 한다.

#### 3단계 — 재무·실체 필터 (하나라도 걸리면 탈락)

| 탈락 사유 | 기준 |
|---|---|
| 창투사·투자회사 | 영업이익이 포트폴리오 평가익이라 실체 아님 |
| 증권·은행·보험·지주 | 영업이익 성격이 제조업과 다름 |
| 부채비율 | 200% 초과 |
| 시가총액 | 700,000,000,000원 초과 |
| 분기 매출 | 2,000,000,000원 미만 |
| 분기 영업이익 | 300,000,000원 미만 |
| 영업이익률 | 3% 미만 |

#### 축 ① 분기 궤적 (5개 분기)

**DART 분기보고서는 누적이 아니라 분기 단독값이다. 4분기 = 연간(11011) − (11013 + 11012 + 11014)**

| 판정 | 기준 | 취급 |
|---|---|---|
| 연속가속 | 영업이익이 3개 분기 이상 연속 증가 | 통과 |
| 개선전환 | 적자·부진 구간을 지나 최근 2개 분기 뚜렷한 개선 | 통과 |
| 등락반복 | 분기별 흑자·적자 또는 급등락 반복 | 탈락 |
| 단발스파이크 | 직전 분기만 튀고 이전 4개 분기는 부진 | 탈락 |

#### 축 ② 이익의 질 (영업활동현금흐름)

| 판정 | OCF ÷ 영업이익 | 취급 |
|---|---|---|
| 우수 | 80% 이상 | 통과 |
| 양호 | 50 ~ 80% | 통과 |
| 주의 | 0 ~ 50% | 보류 (경계종목) |
| 경고 | 마이너스 | **탈락** |

**반드시 함께 확인** — 매출채권 증감, 재고자산 증감, 재무활동현금흐름(차입으로 메웠는지).

#### 축 ③ 수급 전환 (외국인·기관 30영업일)

| 판정 | 기준 | 취급 |
|---|---|---|
| 매수우위 | 30일 누적 순매수 > 0 | 통과 |
| 매수전환 | 30일 누적은 음수인데 최근 5일 > 0 | 통과 |
| 중립 | 거래 미미 | 보류 |
| 매도우위 | 30일 누적 < 0 **이고** 최근 5일도 < 0 | 보류 |

외국인 순매수일수(30일 중 며칠)도 기록한다. 20일 이상이면 강한 신호.

#### 축 ④ 밸류에이션·여력

시가총액은 작을수록 유리(100,000,000,000원 미만이면 10배 시 1,000,000,000,000원으로 현실적). PER 40배 초과는 감점. 52주 고점 대비는 낮을수록 좋으나 **너무 낮으면 하락 이유를 반드시 확인**한다(액면병합 여부 먼저 확인).

#### 최종 판정

- **편입** — 궤적 통과 + 수급 통과 + 현금흐름 우수/양호
- **경계** — 3개 축만 통과. 편입 조건과 확인 시점을 명시
- **제외** — 궤적 탈락 또는 현금흐름 경고

#### 보유 종목 재검증 트리거 (공통)

- 분기 궤적이 등락반복 또는 단발스파이크로 강등
- 영업활동현금흐름이 마이너스로 전환
- 외국인 30일 순매수가 마이너스이고 최근 5일도 마이너스
- 시가총액이 700,000,000,000원 초과
- 부채비율 200% 초과

여기에 더해 **아티팩트 WATCH 각 항목의 `trigger` 필드를 그대로 점검**한다.

### MCP 호출 레시피 (파라미터를 임의로 바꾸지 말 것)

**재무제표**
```
{S}koreaStock-dart_get_financial_statement { stockCode:"052900", year:"2026", reportCode:"11013" }
```
반환 경로 `data.accounts.{revenue|operating_income|net_income|total_assets|total_liabilities|total_equity}.amount_krw` (원)
**반드시 확인** `data.accounts.revenue.fs_name` — `연결재무제표` / `재무제표`(별도). 연도별로 다르면 증가율이 왜곡되므로 리포트에 명시.

**시세**
```
{S}koreaStock-stock_get_quote { stock_code:"219420" }
```
`price, change_rate, market_cap(억원), per, pbr, week52_high, week52_low, sector`. PER·PBR이 **둘 다 0이면 미제공** — 0으로 쓰지 말고 `-`로 표기.

**시세 이력**
```
{S}koreaStock-stock_get_price_history { stock_code:"219420", period:"D", start_date:"YYYYMMDD", end_date:"YYYYMMDD", limit:60 }
```
start_date/end_date를 **반드시 지정**. 생략하면 1건만 반환. 1회 최대 100건.

**투자자 수급**
```
mcp__kis__call-kis-api { group:"domestic_stock", api_type:"inquire_investor",
  params:{ fid_cond_mrkt_div_code:"J", fid_input_iscd:"219420" } }
```
`output[]` 약 30영업일, **배열 첫 행이 가장 최근**. 필드 `stck_bsop_date, stck_clpr, prsn_ntby_qty, frgn_ntby_qty, orgn_ntby_qty`
- 외국인 30일 = `frgn_ntby_qty` 전체 합 / 최근 5일 = 첫 5행 합 / 순매수일수 = `frgn_ntby_qty > 0` 인 날 수

**영업활동현금흐름 (2단계 호출)**
```
{S}opendart-find_company { query:"회사명" }   → stock_code 일치 항목의 corp_code 8자리
{S}opendart-get_full_financial_statement { corp_code:"00276834", bsns_year:"2026", reprt_code:"11013", fs_div:"CFS" }
```
- `fs_div:"CFS"`(연결)가 비면 `"OFS"`(개별)로 재시도. 개별 기준이면 리포트에 명시
- **응답 112KB. 에이전트당 3종목까지만 배정**
- 추출: `sj_nm == "현금흐름표"` 중 `"영업활동현금흐름"` 또는 `"영업활동으로 인한 현금흐름"` → `thstrm_amount`
- 재무상태표에서 `매출채권`·`재고자산`의 `thstrm_amount` / `frmtrm_amount`
- 계정명이 표준형이 아닌 회사가 있다 — `"매출채권 및 기타유동채권"`, `"유동재고자산"` 등

**애널리스트 컨센서스 (커버리지 공백 확인)**
```
mcp__kis__call-kis-api { group:"domestic_stock", api_type:"estimate_perform", params:{ sht_cd:"257720" } }
```
`output1.item_kor_nm`이 빈 문자열이면 커버리지 없음. 전 종목이 비면 **005930(삼성전자)로 대조 호출**해 API 오류인지 확인.

**공시·기업정보**
```
{S}opendart-get_company_info { corp_code:"..." }
{S}opendart-get_largest_shareholders { corp_code:"...", bsns_year:"<전년>", reprt_code:"11011" }
{S}opendart-search_disclosures { corp_code:"...", bgn_de:"YYYYMMDD", end_de:"YYYYMMDD", page_count:30 }
{S}opendart-get_capital_change { corp_code:"...", bsns_year:"<전년>", reprt_code:"11011" }
```
**search_disclosures는 제목만 반환한다.** 매수·편입 판단에 직결되는 공시는 `rcept_no`로 DART 원문(dart.fss.or.kr)을 열어 계약금액·상대방·기간·전환청구 개시일까지 확인한다.

**뉴스·지수**
```
{S}koreaStock-market_get_news { stock_code:"382800", limit:8 }
{S}NaverSearch-search_news { query:"종목명", display:5, sort:"date" }

**rate limit 대응 — 서브에이전트 프롬프트에 그대로 넣을 것**
> "한 메시지에 8~10개 호출을 동시에 넣어 병렬 처리하라. rate limit이 나면 배치를 4~6개로 줄이고 호출 사이에 지연을 넣어 전부 재시도하라. **절대 중간에 멈추지 마라.** 실패 종목은 건너뛰고 계속하라."

| 실적 변곡 전수 (1,132종목) | 에이전트 12개 × 95종목 | 약 12분 |
| 정밀검증 (44종목) | 에이전트 6개 × 8종목 | 약 5분 |
| 현금흐름 (12종목) | 에이전트 4개 × 3종목 | 약 3분 |
| 기업 심층조사 (10종목) | 에이전트 4개 | 약 5분 |

서브에이전트에 종목 목록을 넘길 때는 **파일로 써서 경로만 전달**한다.

### 워크플로 7단계

**1단계** 유니버스 확보 (위 기준)
**2단계** 실적 변곡 전수 스크리닝 — 서브에이전트 10~14개 병렬
**3단계** 재무·실체 필터
**4단계** 상위 40~50종목 정밀검증 — 분기 궤적(5개 분기) + 수급(30영업일) + 시세, 종목당 7회 호출, 에이전트 6~8개
**5단계** 이익의 질 + 보유 종목 트리거 점검 — **세 갈래를 동시에**
  - 신규 후보 상위 12~15종목의 영업활동현금흐름 (에이전트당 3종목)
  - **보유 종목 각각의 `trigger`(아티팩트 WATCH) 점검** → 발동하면 제외 후보
  - **경계종목 각각의 `cond`(아티팩트 BORDER) 점검** → 충족하면 편입 후보
**6단계** 최종 판정 및 diff — 아티팩트 WATCH/BORDER와 대조해 편입·제외·유지 산출
**7단계** 신규 편입 종목 심층 조사 — **신규 편입이 있으면 반드시.** 서브에이전트를 쓰되 종목당 2~3회 검색으로 제한

| 항목 | 출처 |
|---|---|
| 설립연도·대표자·본사·홈페이지 | `opendart-get_company_info` |
| 최대주주와 지분율 | `opendart-get_largest_shareholders` |
| 주력사업 (3~4문장) / 주요 제품 3~5개와 매출 비중 / 주요 고객사 / 경쟁사 / 전방산업 업황 | 웹 검색 |
| 최근 이슈 3~5건 (날짜 포함) | 웹 검색 + `opendart-search_disclosures` |
| 투자포인트 / 리스크 / 재검증 트리거 | 위 자료를 종합해 직접 작성 |

**확인되지 않은 항목은 "확인 불가"로 표기하고 절대 추측하지 않는다.**

### 산출물 ① — 월간 리포트 (아래 순서 그대로)

**(1) 요약** — 유니버스 규모와 단계별 통과 수 / 워치리스트 변동(예: 7종목 → 8종목, 편입 2 / 제외 1) / 코스피·코스닥 지수와 전 회차 대비 / **이번 회차에 판정 불가한 축이 있으면 여기에 명시**

**(2) 편입 종목 — 한 종목씩 상세히**
- 종목명·티커·시가총액(원 단위 풀 콤마)·업종
- **왜 지금 편입되었는가** — 지난 회차엔 없었는데 이번에 들어온 이유를 특정 (예: "2분기 실적 공시로 궤적이 등락반복에서 연속가속으로 전환")
- **4축 각각의 판정과 근거 수치** — 분기 궤적(5개 분기 매출·영업이익 실수치) / 수급(외국인 30일 순매수 주식수, 순매수일수, 최근 5일) / 이익의 질(영업이익·OCF 실수치, 비율, 매출채권·재고 증감) / 밸류에이션(시가총액, PER, 52주 고점 대비)
- 7단계에서 조사한 기업 정보 전체
- **리스크** — 편입했더라도 약점을 반드시 명시
- **재검증 트리거** — 무엇이 확인되면 제외할 것인지 구체적 숫자로

**(3) 제외 종목 — 한 종목씩 상세히**
- 종목명·티커·편입 시점과 편입 시 시가총액
- **어느 축에서 탈락했는가** — 축 이름과 실수치
- **편입 당시 대비 무엇이 바뀌었는가** — 숫자로 비교
- 편입 시점 대비 주가 변동률
- **판단 회고** — 편입 판단에 문제가 있었다면 무엇을 놓쳤는지 솔직히

**(4) 유지 종목 현황** — 표로: 종목명, 티커, 시가총액, 편입 이후 누적 주가 변동률, 4축 상태 변화, **트리거 점검 결과**

**(5) 경계종목 현황** — 각 종목의 **편입 조건 충족 여부**를 명시. 미충족이면 무엇이 얼마나 부족한지 수치로

**(6) 다음 회차 관찰 포인트** — 날짜가 있는 것을 우선 (실적 공시 예정일, 검증 결과 발표, 계약 이행일, 정책 시행일)

**(7) 이번 회차에서 확인하지 못한 것** — 전환사채·신주인수권 오버행, 최대주주 지분 변동, 감사의견·관리종목 이력, 특수관계자 거래, 수주잔고의 질, 경영진 이력·경영권 분쟁 중 확인 못 한 항목

**(8) 사용한 MCP 나열 + 미사용 사유**

**면책** — 조사 결과이며 매수 추천이 아님. 소형주로 유동성이 낮고 변동성이 큼. 투자 판단과 결과는 본인 책임.

리포트는 마크다운 파일로 산출물 폴더에 저장하고 `mcp__cowork__present_files`로 제시한다.
파일명 — `텐베거_월간리포트_<회차>회차_YYYYMMDD.md`

### 산출물 ② — 아티팩트 자동 갱신

리포트 작성 후 **반드시** 아티팩트 `tenbagger-watch`를 갱신한다. 건너뛰지 않는다.

#### ⚠ 아티팩트 원본 파일은 수정할 수 없다

`list_artifacts`가 준 `path`의 파일은 **읽기 전용**이다. 그 경로에 `Edit`/`Write`를 시도하면 막힌다.
**반드시 산출물 폴더에 새 HTML 파일을 만들어 `update_artifact`에 넘긴다.**

#### 절차

> **마커는 이름으로 찾습니다.**
> `WATCHLIST_START` 처럼 **이름이 들어 있는 주석 줄**을 찾으면 됩니다.
> 양옆 등호 개수나 이름 뒤에 붙은 설명 문구는 **달라도 됩니다.**
> 실제로 완성본 예시(`tenbagger-watch-full.html`)는 등호가 더 많고 설명이 붙어 있는데, 같은 마커입니다.
> 갱신할 때는 **START 와 END 사이 블록을 통째로** 바꿉니다.

1. **기존 아티팩트를 읽는다 (0단계에서 이미 읽었으면 재사용).**
2. **새 HTML을 산출물 폴더에 만든다** — 예: `<산출물폴더>/tenbagger-watch.html`
   기존 HTML 전체를 가져와 아래 두 블록만 바꿔 **처음부터 새로 쓴다.**
   - `/* ==== WATCHLIST_START ==== */` ~ `WATCHLIST_END` 사이의 `const WATCH = [...]`, `const BORDER = [...]` → **통째로 교체**
   - `/* ==== CHANGELOG_START ==== */` ~ `CHANGELOG_END` 사이의 `const CHANGELOG = [...]` → **맨 앞에 이번 회차 항목 추가. 기존 이력은 절대 지우지 않는다.**
3. **JS 문법 검사 (필수)**
```bash
python3 -c "
import re
h=open('파일경로',encoding='utf-8').read()
open('/tmp/c.js','w',encoding='utf-8').write(re.findall(r'<script>(.*?)</script>',h,re.S)[-1])
"
node --check /tmp/c.js
```
4. **금액 표기 검사 (필수)** — 억·만·조 축약이 없는지 정규식 `[0-9]+(\.[0-9]+)?\s*[억만조]원` 으로 확인. 걸리면 원 단위 풀 콤마로 교정.
5. ```
   mcp__cowork__update_artifact { id:"tenbagger-watch", html_path:"<2번에서 만든 새 파일>", update_summary:"..." }
   ```
   `mcp_tools`에는 아티팩트가 호출하는 도구를 전부 나열한다 —
   `{S}koreaStock-stock_get_quote`, `{S}koreaStock-stock_get_price_history`,
   `{S}koreaStock-market_get_news`, `mcp__kis__call-kis-api`, `{S}NaverSearch-search_news`

#### WATCH 항목 형식 — 필수 필드를 전부 채운다

```javascript
{code:"219420", name:"링크제니시스", market:"KOSDAQ",
 theme:"반도체 검증 소프트웨어",
 q:"링크제니시스 SECS GEM 스마트팩토리",       // 테마 뉴스 검색어
 traj:"연속가속",     // 연속가속 / 개선전환 / 등락반복 / 단발스파이크
 flow:"매수우위",     // 매수우위 / 매수전환 / 중립 / 매도우위
 cf:"우수", ocfr:318.9,                       // 우수 / 양호 / 주의 / 경고
 mcapIn:376,                                  // 편입 시 시가총액 (억원 숫자 — 이 필드만 억원 단위)
 est:"2003년 12월 설립 · 대표이사 정성우",
 hq:"경기 안양시 동안구 시민대로 401 · linkgenesis.co.kr",
 biz:"주력사업 3~4문장",
 products:["제품명 — 설명 (매출 비중)"],       // 3~5개
 customers:"구체적 기업명",
 competitors:"경쟁사 또는 '확인 불가'",
 industry:"전방산업 업황과 방향",
 shareholder:"최대주주명 지분율% (특수관계인 포함 %)",
 issues:["2026.01.28 — 내용"],                // 3~5건
 point:"투자 포인트 2~4문장",
 risk:"리스크 2~4문장",
 trigger:"재검증 트리거 — 무엇이 확인되면 제외할지 구체적 숫자로",
 src:[["출처명","URL"]]}
```

#### BORDER 항목 형식

WATCH와 같되 `point` / `risk` / `trigger` 대신 —
```javascript
 why:"왜 아직 편입하지 않았는가 — 어느 축이 미달인지 수치로",
 cond:"편입 조건 — 무엇이 어떻게 바뀌면 편입할지",
 when:"확인 시점 — 2026년 2분기 실적 공시 후 등"
```

#### CHANGELOG 항목 형식

```javascript
{date:"2026-09-01", title:"월간 재실행 N회차",
 summary:"이번 회차 요약 2~3문장",
 added:[{name:"종목명", code:"123456", why:"편입 사유를 구체적 수치와 함께 2~3문장"}],
 removed:[{name:"종목명", code:"123456", why:"어느 축에서 왜 탈락했는지 수치와 함께 2~3문장"}]}
```

`why`는 **반드시 구체적 수치를 포함**한다. "실적이 나빠져서" 같은 서술은 쓰지 않는다.
편입·제외가 없으면 `added:[]`, `removed:[]`로 두되 `summary`에 "변동 없음"과 그 이유를 쓴다.
**트리거 점검만 한 회차도 CHANGELOG에 기록한다.**

#### 아티팩트 갱신이 끝내 실패하면

작업을 버리지 말고 산출물 폴더에 아래를 남기고 사용자에게 알린다.
- `tenbagger-watch.html` — 갱신된 전체 HTML
- 리포트 파일
- 갱신할 WATCH/BORDER/CHANGELOG 블록을 담은 패치 파일

보고 문구 — "아티팩트 자동 갱신에 실패했습니다. 갱신된 HTML을 산출물 폴더에 만들어 뒀으니 다음 대화에서 '아티팩트 갱신해줘'라고 하시면 반영하겠습니다."

### 실행 후 사용자에게 보고할 것

1. 편입·제외 요약 (종목명과 한 줄 사유)
2. **트리거에 걸린 보유 종목이 있으면 맨 먼저 알린다**
3. 리포트 파일 링크 (`mcp__cowork__present_files`)
4. 아티팩트 갱신 완료 여부
5. 다음 회차 관찰 포인트

### 주의사항

- **DART API는 rate limit이 강하다.** 서브에이전트 프롬프트에 재시도 지시를 반드시 넣는다.
- **분기보고서는 누적이 아니라 분기 단독값이다.** 4분기는 연간에서 1~3분기를 뺀다.
- **연결/별도 재무제표가 섞이는 종목이 있다.** `fs_name`을 확인하고 기준이 다르면 증가율이 왜곡되므로 리포트에 명시한다.
- **금융·지주·창투사는 영업이익의 성격이 다르다.** 반드시 제외한다.
- **실적 공시 직후(3월 말·5월·8월·11월 중순)에는 궤적 판정이 크게 바뀐다.** 이때는 특히 꼼꼼히 본다.
- 매월 1일 실행이므로 **4·6·9·12월 1일 회차는 직전 분기 공시가 막 반영된 시점**이라 변동이 가장 크다. 그 외 회차는 공시 변화가 없어 트리거 점검 위주가 될 가능성이 높다 — 중복 점검 절차를 반드시 먼저 돌린다.
