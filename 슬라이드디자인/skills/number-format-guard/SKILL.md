# 숫자 표기 검증 가드 (number-format-guard)

산출물에 숫자를 쓰는 모든 작업에서, **저장 직전**과 **완료 보고 직전**에 이 절차를 실행한다.
"서식을 적용했다"는 호출 성공 응답은 증거가 아니다. **읽어서 확인한 것만 증거다.**

---

## 1. 표기 규칙 (위반 시 즉시 자동 교정)

> **통화는 `brand.config.md` 의 `Currency` 가 정한다.** 기본값은 원화이고, 아래 예시도 원화 기준이다.
> 다른 통화를 쓰면 「최소 단위 + 세 자리 콤마」 원칙은 그대로 두고 단위 표기만 바꾼다.
> 축약 금지(만/억/조)는 **한국어 금액 표기에 해당하는 조항**이다. 다른 언어권이면 그 언어의 축약(k, M, bn 등)에 같은 원칙을 적용한다.

| 대상 | 규칙 | 서식 코드 |
|---|---|---|
| 금액 | **통화 최소 단위 + 세 자리 콤마.** 원화 예: `1,234,567,890원` | `#,##0` |
| 건수·개수·횟수 | 콤마 | `#,##0` |
| 면적 | 콤마 + 소수 2자리 | `#,##0.00` |
| 비율 | 소수 1자리 + % | `0.0"%"` |
| 날짜 | ISO | `yyyy-mm-dd` |
| 식별번호 | **콤마 금지**. 앞자리 0이면 텍스트 | `@` |

**만/억/조 축약 전면 금지.** `12.3억`, `123,456만`, `3억원 미만` 모두 위반.

식별번호에 해당하는 것: 사건번호, 공고번호, 물건관리번호, 공매번호, 공매조건번호, 사업자번호, 법인등록번호, 계좌번호, 연번, 회차.

### 축약 허용 예외 (이것만)
1. 사용자가 명시적으로 "억/만/축약"으로 써 달라고 요청
2. **그래프 축 라벨만**의 가독성 — 본문 데이터·셀 값·구간 라벨은 예외 아님
3. 외부 출처 원문 인용 (출처 병기)

### 구간 라벨(bin)은 본문 데이터다
`감정가 규모대`, `채권액 구간` 같은 분류 열의 값은 셀에 저장되는 본문 데이터이므로 풀 콤마를 쓴다.

- 금지: `③ 3억~5억원`
- 사용: `③ 300,000,000~500,000,000원`

라벨이 길어져 차트 가독성이 떨어지면 **차트 종류를 가로 막대(BarStacked)로 바꿔** 해결한다. 라벨을 줄이지 않는다.
정렬이 깨질 수 있으므로 라벨 앞에 `①②③…` 순번을 붙이고, 라벨을 바꿏 뒤에는 피볋 행 필드를 `sort-field(Ascending)`으로 재정렬한다.

## 2. Excel 함정 — 반드시 알고 있을 것

### 함정 A: 피볋 값 필드의 number_format 인자는 조용히 무시된다
`pivottable_field(add-value-field, number_format: "#,##0")`는 `success: true`를 반환하면서도
실제 셀 서식은 `G/표준`으로 남는 경우가 있다.

**대응:** 값 필드를 추가한 뒤 **별도 호출**로 다시 지정한다.

```
pivottable_field(action: "set-field-format",
                 pivot_table_name: "PT_xxx",
                 field_name: "<customName으로 지정한 이름>",
                 number_format: "#,##0")
```

`field_name`에는 원본 열 이름이 아니라 `custom_name`으로 붙인 표시 이름을 넣는다.

### 함정 B: 시트를 다른 파일로 복사하면 서식은 남고 참조는 깨진다
`worksheet(copy-to-file)`로 시트를 옮기면
- 셀 숫자 서식: 유지됨
- 피볋 원본: `'C:\...\원본파일.xlsx'!TBL_XXX` 외부 참조로 바뀌섬
- 피볋차트: 일반 차트로 강등, 슬라이서: 연결 끊김
- 수식: 외부 파일 경로가 박힌 채로 남음

**대응:** 처음부터 최종 저장 위치에 파일을 만든다. 이미 옮겼다면 `pivottable(list)`로 `sourceData`를 확인하고, 외부 경로가 보이면 피볋·차트·슬라이서를 삭제 후 재생성한다.

### 함정 C: 표·피볋 셀에 range_format을 쓰면 새로고침 때 지워진다
숫자 서식은 표 본문에는 `range(set-number-format)`, 피볋에는 `pivottable_field(set-field-format)`로만 건다.

## 3. 저장 전 필수 검증 (건너뛰지 않는다)

### 3-1. 숫자 서식 읽기 재검증
집계·금액이 들어간 **모든 시트**에 대해 실제 서식을 읽는다.

```
range(action: "get-number-formats", sheet_name: "<시트>", range_address: "<값 영역>")
```

`G/표준`이 하나라도 보이면 → 미적용이다. 교정 후 다시 읽어 확인한다.

### 3-2. 눈으로 확인
```
screenshot(action: "capture", sheet_name: "<시트>", range_address: "<값 영역>", quality: "High")
```
콤마가 실제로 찍혀 있는지 본다. 숫자가 `5764346199`처럼 보이면 실패다.

### 3-3. 축약 문자열 수색
셀 값·헤더·차트 제목·KPI 라벨·시트 설명문에서 아래를 찾는다.

```
억  만원  조원  천만  백만
```

`range_edit(action: "find")`로 시트별 검색하고, 발견되면 원 단위 풀 콤마로 교정한다.
(주소의 `만안구`·`성남시` 같은 지명 오탐은 제외)

### 3-4. 총합계 대조
피볋 총합계 = 원자료 행 수인지 확인한다. 불일치하면 보고한다.

---

## 4. 보고 원칙

- 검증하지 않은 항목을 "확인했다"고 쓰지 않는다.
- "금액 열은 전부 콤마" 같은 문장은 **3-1과 3-2를 실제로 수행한 뒤에만** 쓴다.
- 검증 범위를 명시한다. 예: "원자료 J~M열, 피볋집계 6개 피볋 값 필드 서식을 읽어 확인"
- 검증하지 못한 부분이 있으면 그대로 밝힌다.

## 5. 셀프 체크리스트

저장 직전 아래에 모두 예라고 답할 수 있어야 한다.

- [ ] 모든 금액·건수 셀의 서식을 **읽어서** 확인했는가
- [ ] 피볋 값 필드마다 `set-field-format`을 별도로 걸었는가
- [ ] 스크린샷에서 콤마가 눈에 보이는가
- [ ] 억/만/조 문자열을 검색했는가 (셀·헤더·차트 제목·구간 라벨 전부)
- [ ] 식별번호 열에 콤마가 없는가
- [ ] 피볋 `sourceData`가 외부 파일 경로가 아닌가
- [ ] 피볋 총합계가 원자료 건수와 일치하는가
